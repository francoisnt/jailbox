# 3.2. JailIDE repository split charter

## Goal

Split the project into independently installed products:

```text
JailIDE -> jailbox -> Podman
orchestrator --------> jailbox -> Podman
```

jailbox remains the generic machine-facing sandbox substrate; JailIDE owns the
human configuration and editor workflow. The dependency points only toward
jailbox.

## Sequence

Implement the indexed plans in filename order. Version precedes digest because
the release version is hashed; digest precedes ownership-label removal because
it becomes the reuse gate; JailIDE exists and passes its gates before core
removes the surfaces it replaces.

## Product boundary

jailbox owns canonical configuration and validation, images, Podman lifecycle,
filesystem and egress policy, SSH generations and transport, deterministic
identity, machine status/connection data, and portable/runtime gates. SSH and
remote IDE-server runtime prerequisites stay generic core behavior. A missing
or changed prerequisite is fixed in jailbox and requires a new compatible
jailbox release before JailIDE claims support; this coordination point remains
until a public downstream wrapper-setup extension is designed. JailIDE
owns `jailide.conf`, init, editor discovery/validation, profiles, bootstrap
destinations, launch/diagnostics, editor pins, and portable/editor gates.

End-state jailbox has no config files, `init`, `--config`, `EDITOR`,
`JAILBOX_EDITOR`, editor launch/discovery, profiles, bootstrap composition,
`ssh-config`, or editor gate. Neither product owns worktrees, external
credentials, agent selection, scheduling, or Git integration.

## Repository layout

This checkout remains jailbox. The clean locally excluded `jailide/` clone
stays nested through 03.2.13. Plan 03.2.10 fast-forwards it from the local
jailbox checkout to the exact coordinated core commit before reduction.
03.2.14 moves it host-side to a user-selected sibling, adds its origin, removes
the local exclude, and proves neither product depends on nesting.

## Security invariants

- Container roots remain read-only, with capabilities dropped and
  `no-new-privileges`.
- No container-engine socket is mounted.
- Project runtime state remains outside the project.
- Core validates and read-only mounts known launch inputs; callers protect
  their own policy inputs.
- Egress mode has no direct route and HTTP(S) uses the allowlisting proxy.
- SSH uses strict host-key checking and project-scoped pinned state.
- Each new container generation gets fresh client/server credentials; resume
  preserves and validates that generation.

Persistent home content is sandbox-controlled state trusted across policy and
version changes. Server material is read-only and client secrets stay
host-only. Digest and structure validation prevent weakened resume. Guarantees
cover one lifecycle command at a time; locking remains backlog work.

## Acceptance criteria

- Each product exposes only its owned surface through the documented executable
  and environment boundary.
- All indexed plans and their gates pass in order.
- Both final repositories have independent versions, installation, state,
  documentation, gates, remotes, and releases.
- JailIDE's real editor gate detects remote-server runtime regressions, while
  jailbox owns and releases the prerequisite fix before compatibility is
  claimed.

## Non-goals

- Plugins, a private API, a separate protocol version, or shared utilities.
- Automatic dependency installation or version matching.
- Moving SSH out of core or allowing JailIDE to call Podman.
- Automatic cleanup/replacement, persistent integrity monitoring, or lifecycle
  serialization.
