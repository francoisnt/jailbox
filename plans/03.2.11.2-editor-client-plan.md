# 3.2.11.2. Prepare the editor client

## Intent

### Goal and place in the sequence

Read the two umbrella plans first. Implement after 03.2.11.1. Prepare the
frontend's editor preflight, bootstrap-host contribution, connection-record
consumer, settings publication, and editor launch. Public dispatch remains
unchanged until 03.2.11.4. All new frontend implementation is in
`host/frontend/` and consumes no private core functions or state.

### Editor selection and diagnostics

Select the editor from `EDITOR` in the selected configuration file. When unset
or empty, discover available Codium followed by Code. Invalid file selections
or missing explicitly selected binaries refuse without fallback. Inherited
`JAILBOX_EDITOR` and shell `EDITOR` have no effect, including invalid values.
Require the selected binary and its Remote SSH extension in the inventory used by the
launched editor: `jeanp413.open-remote-ssh` for Codium and
`ms-vscode-remote.remote-ssh` for Code. Failed inventory queries refuse even
when stdout looks successful. Query on every editor launch, including reopen.
Editor/extension versions are not runtime requirements or warning triggers.

Editor launch validation carries its own diagnostic obligation. A refusal must
name every requirement it found unmet and the resolved editor together with the
precedence step that selected it, so a user can correct the setup from one
refusal instead of discovering the next problem on the next launch. Because
validation precedes any lifecycle mutation, a refused launch leaves no
resources behind and is safe to repeat as a diagnostic.

Supply the selected editor's existing bootstrap destinations to 03.2.11.1's
composer only for nonempty `EGRESS_ALLOW`. Include Codium's `github.com` and
`githubusercontent.com` and the existing Code destinations currently in
`host/network.sh`. No editor discovery or bootstrap addition belongs in
headless file composition or explicit file validation.

### Connection records and profiles

Consume only the public `connection-info` records, including its required
field order, meanings, ASCII name grammar, uniqueness, NUL framing, and valid
opaque trailing fields. Failed child commands are failures regardless of
stdout. Successful `up` cannot substitute for current connection validation.

Generate isolated profiles beneath `~/.local/state/jailbox/editor-profiles/`
using reported connection data. Set editor `http.proxy` exactly when the
reported `proxy_url` is nonempty, and omit it otherwise. Preserve every accepted
connection value through JSON encoding and decoded settings inspection,
including spaces, quotes, and backslashes. Invalid records/settings prevent
editor launch. Preserve the existing settings on failed preparation or
publication; clean operation-owned temporary files, report cleanup failures,
and preserve caller traps/settings. Remote proxy environment policy remains
core-owned SSH session behavior, as required by the umbrella security contract.

Generated editor settings must omit the existing `terminal.integrated.env.linux`
proxy block. SSH supplies the uppercase and lowercase HTTP/HTTPS/NO_PROXY
session variables; the frontend uses only the reported `proxy_url` for editor
`http.proxy`. 03.2.11.4 owns removing the old writer's block and migrating its
positive assertion when the prepared frontend becomes active. Portable tests
here assert that the prepared settings omit that block in both network modes.

Retain core's `ssh-config` command for human connection instructions as defined
by 03.2.09. The frontend never parses that output: `connection-info` remains its
only connection-data source. README supplies the editor setting name paired
with the path ssh-config reports.

### Verification and handoff

- Portable tests cover selection precedence, invalid selections, missing
  binaries/extensions, failed inventory with plausible stdout, differing
  installed versions, complete diagnostic context, and no machine invocation
  after preflight failure. Prove inherited `JAILBOX_EDITOR` and shell `EDITOR`
  cannot override file selection or automatic discovery, even when invalid.
- Test connection framing and semantic validation, valid future trailing
  fields, child failures, JSON round trips, decoded inspection, and publication
  failures that prevent editor launch. Retain 03.2.07.1's publication guarantees.
- Test bootstrap-host contributions and their absence for unfiltered launches.
- Run `tests/run portable`; keep existing editor behavior working before the
  switchover. Run the editor gate for affected active editor integration.
- 03.2.11.4 owns replacing `host/editor.sh`, moving preflight ownership,
  removing core reads of editor state and the image hook, and wiring these
  prepared components into the real CLI. Its acceptance requires preflight
  before any machine command and editor launch only after validated records.
- 03.2.11.5 owns full real-editor integration and filtered policy-switch
  verification. Extend these fixtures there rather than create a parallel suite.

### Acceptance criteria

Prepared frontend components pass their focused tests without private core
access. They accept the public connection contract and preserve settings
publication guarantees, with no editor-generated terminal proxy environment.
No external command behavior is switched early.

## Implementation detail

The file-policy component from 03.2.11.1 provides frontend-owned parsed values;
this component provides editor-specific policy additions. Keep connection
framing and JSON handling in focused helpers, not a general serialization
framework. Inspect existing editor test setup when moving smoke behavior so
it does not accidentally retain a dependency on private core state. Remove
superseded implementations at the 03.2.11.4 switchover.
