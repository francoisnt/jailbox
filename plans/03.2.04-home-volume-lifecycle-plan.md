# 3.2.04. Home-volume lifecycle, stop, and clean

## Goal

Make data retention depend on creation-time metadata, independently of digest
compatibility.

## Sequence

Implement after `03.2.02-configuration-digest-plan.md` and
`03.2.03-resource-identity-plan.md`, before constrained up, preserving
`archive/02-explicit-stop-plan.md`.

## Behavior

Add strict `EPHEMERAL_HOME=true|false`, default `EPHEMERAL_HOME=true`.
Label new homes with `jailbox.ephemeral-home=true|false`. Unlabeled legacy
homes always read false and are never relabeled. Any other present value is
corrupt: preserve, warn, and refuse to guess. Persistent homes survive
generations, policies, and versions; ephemeral homes survive only their
container generation.

An orphaned `EPHEMERAL_HOME=true` volume whose development-container object no
longer exists is never reusable, even if every remaining digest matches. It
blocks `up` until `jailbox stop` removes it. Persistent and legacy-false
volumes remain eligible for exact-name reuse.

Accept and preserve an unlabeled home for requested false; requested true is a
persistent-to-ephemeral change that refuses with warned clean guidance. This
makes the ordinary upgrade non-destructive with the false value JailIDE writes.
Core never labels a volume it did not create. Replace only jailbox-marked proxy
blocks in reused homes and otherwise preserve contents.

Ephemeral-to-persistent uses `stop` then `up`. Persistent/legacy-to-ephemeral
uses warned `--clean` then `up`. Mismatch refuses before mutation.

`stop` removes both containers and all project networks, then removes only a
valid true home. It preserves false, legacy, and malformed-label homes.
Images survive stop. `--clean` warns and removes all runtime state, every home,
and exact `PROJECT_DEV_IMAGE`, `JAILBOX_IMAGE`, and `PROXY_IMAGE`, regardless
of provenance. External `DEV_IMAGE` is untouched unless deliberately named as
one of those three.

Both commands delete occupants of exact derived names regardless of digest,
legacy status, structure, or labels. 03.2.03 owns documentation of this
destructive name-as-identity collision boundary; this plan implements the
cleanup behavior and warnings. Neither recovery runs automatically.

## Tests and documentation

Cover valid, legacy, corrupt, orphaned and mode-change states, interrupted stop,
contents, exact image deletion, status, and warnings. Update help, README,
threat model, and release notes.

Implement volume metadata in `host/container-runtime.sh`; update stop/clean
dispatch, public help, lifecycle units, and runtime tests.

## Acceptance criteria

- New homes record the default/effective mode and legacy homes remain false.
- Stop applies stored policy; clean always removes home and exact derived images.
- Directional recovery is non-mutating until explicitly executed.
- Post-stop status is absent only without preserved inventory; clean is absent.
- Every clean recommendation warns that home and runtime state are permanently
  deleted.
- An orphaned ephemeral home blocks up until stop removes it; it is never
  adopted into a new generation.

## Non-goals

- Digest-gating homes or guessing malformed metadata.
