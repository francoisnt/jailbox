# 3.2.12. `jailide.toml` format and `jailide init`

## Goal

Implement JailIDE's strict human-readable project configuration and atomic
initialization without duplicating jailbox's core schema.

## Sequence

Implement in the JailIDE repository after 03.2.11. It consumes
`jailbox --version`, `config-schema`, and `status` from 03.2.01/08 and
precedes launch composition in 03.2.13.

## Command and file interface

The public surface owned here is:

```text
jailide [--config PATH] [--editor code|codium]
jailide init
```

The default file is `$PROJECT_DIR/jailide.toml`. `--config PATH` selects one
complete alternate file but does not remove the default anchor requirement
defined in 03.2.13. User messages name JailIDE, not jailbox; no
`jailbox.conf` compatibility reader or migration command exists. The format
is JailIDE's own: it deliberately does not inherit jailbox's shell-era
`KEY=value` grammar.

Implement the strict-data parser and atomic publication in JailIDE-owned Go
packages with clear command/flag, parsing, and initialization boundaries.
JailIDE contains no core lifecycle, Podman, SSH, or image dependencies.

## Schema discovery

At invocation start, resolve and version-check one installed jailbox path as
defined in 03.2.11. Execute `config-schema` once and parse exactly
`KEY<TAB>scalar|array` records. Reject malformed lines, duplicate keys,
invalid uppercase names, unknown types, or absence of a core key JailIDE needs
for composition. Accept unknown additional valid core keys and preserve their
declaration order. Do not carry a static core key list.

The file may contain discovered core keys other than `WRAPPER_SETUP`, plus
JailIDE-only `EDITOR`. Core values are exported later and validated again by
jailbox. JailIDE validates only representation and any behavior it must
understand for composition (`EGRESS_ALLOW`, `READONLY_PATHS`, and
`EPHEMERAL_HOME`). `WRAPPER_SETUP` remains a jailbox caller interface, but is
not part of JailIDE's public configuration. JailIDE does not accept it in
`jailide.toml`, expose a JailIDE environment-variable or command-line
equivalent, include it in `jailide init`, or document it as a JailIDE setting.
Users customize their development image in the Containerfile that JailIDE
already wraps. JailIDE uses the jailbox interface internally only to contribute
its own embedded editor setup in 03.2.13.

## Strict file grammar

`jailide.toml` is one TOML document whose top level maps configuration key
names to values. Parse it with one pinned, reviewed TOML library; the file
is inert data and is never evaluated. Value typing is ordinary schema
validation over standard TOML, not a custom dialect:

- A scalar key maps to one TOML string; its decoded bytes are the value,
  byte for byte. Any other value type — boolean, integer, float, date-time —
  is rejected with a diagnostic telling the user to quote the value. An
  empty string is a valid present value.
- An array key maps to an array of strings in file order. An empty array is
  explicitly empty; an absent key is unset. Empty-string members are
  invalid, matching the environment contract; so is any non-string member.
- Reject unknown keys, a string where an array is expected or the reverse,
  `EDITOR` as an array, and tables, inline tables, dotted keys, and arrays
  of arrays. Duplicate keys are already invalid TOML.
- Comments are ordinary TOML comments. Basic, literal, and multi-line
  strings are all accepted; members may contain commas and, through
  multi-line strings, newlines.

Report parse and validation failures with the file path and, where the
library provides it, the line; parsing is all-or-nothing.

Map array members in order to `JAILBOX_CONFIG_<KEY>_0` through contiguous
indices. Map scalars to bare `JAILBOX_CONFIG_<KEY>`. Preserve an explicitly
empty array as an empty bare variable and omit unset keys so core applies
defaults. Unlike the retired line-based grammar, the file can represent
newline-containing members; only values that are not valid UTF-8 remain
expressible through the environment interface alone.

## Editor selection input

Store file `EDITOR` only as JailIDE state. Final precedence is:

```text
--editor
JAILIDE_EDITOR
file EDITOR
codium when available
code
```

Validate explicit values as exactly `code` or `codium`. Discovery and
Remote SSH validation belong to 03.2.13. No `EDITOR`,
`JAILBOX_EDITOR`, or `JAILBOX_CONFIG_EDITOR` is exported to core.

## `jailide init`

Initialization:

1. resolves/version-checks jailbox and parses the live schema;
2. resolves the canonical project/default-file path without accepting symlinked
   components;
3. refuses if any object already occupies `jailide.toml`;
4. runs `jailbox status` with no configuration and requires stdout to be
   exactly `absent\n`;
5. constructs the minimal template, verifies every core key and type against
   the discovered schema, and validates it through the same parser; and
6. atomically publishes without overwriting, removing temporary output on
   failure.

The template includes ordinary minimal values and explicit
`EPHEMERAL_HOME = "false"`, with a comment that it preserves editor servers,
tools, shell configuration, history, and other sandbox-controlled content
across generations and policy/version changes. Running, stopped, partial, or
malformed resource sets refuse without writing. A preserved home requires
warned `jailbox --clean` first.

## Security invariants

Configuration is strict data and cannot execute shell. Unknown core additions
cannot bypass schema classification. No mutation occurs before complete
validation. Initialization does not call Podman directly and cannot overwrite
an existing path.

## Tests and documentation

Write Go unit tests for the parser and init; add fake-jailbox schema/status
fixtures for malformed, additive, missing, and incompatible versions. Cover
string and string-array grammar, rejection of non-string values (`false`,
`1.10`, dates) with the quote-the-value diagnostic, basic/literal/multi-line
strings, newline-containing members, commas, empty string/array/unset forms,
duplicate keys, rejection of tables, inline tables, dotted keys, and arrays
of arrays, the core's 512-member support floor without a JailIDE-specific
maximum, editor precedence, symlink rejection, rejection of `WRAPPER_SETUP`
in `jailide.toml`, every status value/partial diagnostic, publication races,
and cleanup.

Document the strings-only schema, representation mapping, editor precedence,
template, persistence tradeoff, and lack of automatic `jailbox.conf`
migration. Run JailIDE `tests/run unit`.

## Acceptance criteria

- Any compatible discovered core key can be parsed and exported without a
  JailIDE release, except the deliberately reserved `WRAPPER_SETUP` key;
  malformed schemas and files fail before mutation.
- Scalars and arrays map byte-for-byte and deterministically to the
  canonical environment grammar, including commas, newlines, and explicit
  empty/unset.
- Editor precedence is exact and never leaks an editor key to jailbox.
- JailIDE exposes no caller-configurable wrapper setup surface; only its
  product-owned editor setup is composed internally for jailbox.
- Init writes one schema-valid, explicit-persistent template only for exact
  absent state and never overwrites or leaves a partial file.

## Non-goals

- Core file parsing, schema duplication, arbitrary shell, non-string value
  types, or automatic migration from `jailbox.conf`.
