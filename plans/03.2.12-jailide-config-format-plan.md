# 3.2.12. `jailide.conf` format and `jailide init`

## Goal

Implement JailIDE's strict human-readable project configuration and atomic
initialization without duplicating jailbox's core schema.

## Sequence

Implement in the reduced JailIDE repository after 03.2.11. It consumes
`jailbox --version`, `config-schema`, and `status` from 03.2.01/08 and
precedes launch composition in 03.2.13.

## Command and file interface

The public surface owned here is:

```text
jailide [--config PATH] [--editor code|codium]
jailide init
```

The default file is `$PROJECT_DIR/jailide.conf`. `--config PATH` selects one
complete alternate file but does not remove the default anchor requirement
defined in 03.2.13. Rename retained parser/init tests and user messages from
jailbox to JailIDE; no `jailbox.conf` compatibility reader or migration
command exists.

Put canonical JailIDE command/flag declarations in its retained/retargeted
public API module and parser/usage in its entrypoint/common module. Keep the
strict-data parser and atomic-publication behavior with history, while removing
core lifecycle, Podman, SSH, and image dependencies from those modules.

## Schema discovery

At invocation start, resolve and version-check one installed jailbox path as
defined in 03.2.11. Execute `config-schema` once and parse exactly
`KEY<TAB>scalar|array` records. Reject malformed lines, duplicate keys,
invalid uppercase names, unknown types, or absence of a core key JailIDE needs
for composition. Accept unknown additional valid core keys and preserve their
declaration order. Do not carry a static core key list.

The file may contain discovered core keys plus JailIDE-only `EDITOR`. Core
values are exported later and validated again by jailbox. JailIDE validates
only representation and any behavior it must understand for composition
(`EGRESS_ALLOW`, `READONLY_PATHS`, and `EPHEMERAL_HOME`).

## Strict file grammar

Retain the settled `KEY=value` data grammar, whitespace/comment handling,
optional value quoting, key-name validation, path/error source diagnostics,
all-or-nothing parsing, and the prohibition on sourcing/evaluation. Rewrite
documentation and fixtures for `jailide.conf`.

- A scalar key occurs at most once and its value is one data string.
- An array key repeats once per member, in file order.
- One empty array occurrence means explicitly empty.
- Empty and non-empty occurrences mixed together are invalid.
- Repeating a scalar, using an unknown name, or using `EDITOR` as an array is
  invalid.
- File array members have no comma or other separator; commas are ordinary
  bytes.

Map array line one to `JAILBOX_CONFIG_<KEY>_0`, then contiguous indices.
Map scalars to bare `JAILBOX_CONFIG_<KEY>`. Preserve an explicitly empty array
as an empty bare variable and omit unset keys so core applies defaults.

Line boundaries cannot represent a member containing newline, and the parser
cannot reliably detect whether two real lines were intended as one member.
Document that limitation honestly. Direct indexed environment callers have no
equivalent restriction. Plan 7 must confirm the widening consequence before a
writable-array feature ships.

## Editor selection input

Store file `EDITOR` only as JailIDE state. Final precedence is:

```text
--editor
JAILIDE_EDITOR
file EDITOR
codium when available
code
```

Validate explicit values as exactly `code` or `codium`. Discovery and
Remote SSH validation belong to 03.2.13. No `EDITOR`,
`JAILBOX_EDITOR`, or `JAILBOX_CONFIG_EDITOR` is exported to core.

## `jailide init`

Initialization:

1. resolves/version-checks jailbox and parses the live schema;
2. resolves the canonical project/default-file path without accepting symlinked
   components;
3. refuses if any object already occupies `jailide.conf`;
4. runs `jailbox status` with no configuration and requires stdout to be
   exactly `absent\n`;
5. constructs the minimal template, verifies every core key and type against
   the discovered schema, and validates it through the same parser; and
6. atomically publishes without overwriting, removing temporary output on
   failure.

The template includes ordinary minimal values and explicit
`EPHEMERAL_HOME=false`, with a comment that it preserves editor servers,
tools, shell configuration, history, and other sandbox-controlled content
across generations and policy/version changes. Running, stopped, partial, or
malformed resource sets refuse without writing. A preserved home requires
warned `jailbox --clean` first.

## Security invariants

Configuration is strict data and cannot execute shell. Unknown core additions
cannot bypass schema classification. No mutation occurs before complete
validation. Initialization does not call Podman directly and cannot overwrite
an existing path.

## Tests and documentation

Retarget `tests/unit/config-parser.sh` and `init-config.sh`; add fake-jailbox
schema/status fixtures for malformed, additive, missing, and incompatible
versions. Cover scalar/array grammar, commas, empty/unset, the core's 512-member
support floor without a JailIDE-specific maximum, newline documentation, editor
precedence, symlink rejection,
every status value/partial diagnostic, publication races, and cleanup.

Document the exact grammar, representation mapping, editor precedence,
newline limitation, template, persistence tradeoff, and lack of automatic
`jailbox.conf` migration. Run JailIDE `tests/run portable`.

## Acceptance criteria

- Any compatible discovered core key can be parsed and exported without a
  JailIDE release; malformed schemas and files fail before mutation.
- Scalars and repeated arrays map byte-for-byte and deterministically to the
  canonical environment grammar, including commas and explicit empty/unset.
- Editor precedence is exact and never leaks an editor key to jailbox.
- Init writes one schema-valid, explicit-persistent template only for exact
  absent state and never overwrites or leaves a partial file.

## Non-goals

- Core file parsing, schema duplication, arbitrary shell, newline escaping, or
  automatic migration from `jailbox.conf`.
