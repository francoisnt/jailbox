# 3.2.01. Release version stamping and bump policy

## Goal

Stamp each build with an exact version, expose `jailbox --version`, and make
pre-1.0 bump suggestions compatible with JailIDE's declared range.

## Sequence

Implement after 03.1 and before the digest, which hashes this exact version.

## Behavior

Stable output is exactly:

```text
jailbox 0.8.0
```

Installed packages report their build version; source checkouts report one
documented development spelling. `--version` is configuration-independent,
non-mutating, needs no Podman, and writes only the stable value to stdout.
Tarball construction stamps a version file in the release tree from the
`vMAJOR.MINOR.PATCH` already validated by `scripts/build-tarball.sh`, without
rewriting tracked source or consulting Git at runtime. `--version` and the
digest consume that same value. Install/update retain it and release validation
rejects mismatches. Source and released versions intentionally produce
incompatible digests.

Declare the flag in `host/public-api.sh` and generated API comparison. Before
1.0, adding a key or CLI flag is patch; removing or changing one is minor.
Update both policy data and `suggest_bump` in `scripts/release.sh`.

Before 1.0 JailIDE uses a minor-line range such as `>=0.8.0,<0.9.0`. After
1.0, normal major-version compatibility applies: additions are minor while
removals/changes are major. jailbox's release version is the sole API/schema
version. Public review covers environment keys, `config-schema`, machine
schemas, and commands. Product versions and release schedules remain
independent.

Plan 03.2.10 extracts the generic implementation of version selection,
packaging, and release Git safety into `shell-release-toolkit`. This plan
remains authoritative for jailbox's version output and bump semantics; toolkit
adoption must preserve them byte for byte and leaves jailbox's public-API
classifier product-owned.

## Tests and documentation

Portable tests cover dispatch, source/package spellings, build/install/update,
API classification, and suggested bumps. Document both spellings and policy.

## Acceptance criteria

- Source and installed copies report the documented exact value.
- Packaging and lifecycle retain the stamp.
- Added interfaces suggest patch and removed/changed interfaces suggest minor.
- Source and installed versions cannot reuse each other's resources.

## Non-goals

- Registry lookup, a separate protocol version, dependency installation, or
  coupled product versions.
