# 3.2.11. JailIDE repository, installation, and gates

## Goal

Convert the existing history-sharing `jailide/` clone into an independent,
MIT-licensed JailIDE repository with its own executable, installation/state
roots, toolkit-backed release machinery, documentation, plans, and
portable/editor gates.

## Sequence and divergence point

Implement after 03.2.10 adopts the local `shell-release-toolkit` candidate,
03.2.10.1 pins `jailutils`, and jailbox plans
03.2.01–03.2.10.1 are one reviewed coordinated commit. Before editing the
clone:

1. record the full jailbox commit identifier;
2. in `jailide/`, fetch that identifier from the local `~/project` checkout,
   not the unpublished `jailbox-upstream` remote;
3. prove JailIDE's current HEAD is an ancestor of the identifier;
4. fast-forward only to that exact commit; and
5. record it in JailIDE documentation/release metadata as the divergence point.

Abort on ancestry or dirty-worktree failure. After the first reduction commit,
never merge or fast-forward a later jailbox commit wholesale. Port required
interface adaptations explicitly and record the tested jailbox artifact/commit.

Keep the clone nested through 03.2.14 because only `~/project` is confirmed
reachable. Preserve `/jailide/` solely in jailbox `.git/info/exclude`; never
add it to tracked `.gitignore`. Confirm `scripts/lint.sh`, unit discovery,
`tests/run`, and `scripts/build-tarball.sh` in jailbox do not descend into
the clone.

## Selective repository reduction

Use history-preserving moves for retained editor/configuration behavior. Remove
from JailIDE the core-only executable and implementation:

- `jailbox`, `host/container-runtime.sh`, `host/dev-image.sh`,
  `host/downloader-proxy.sh`, `host/network.sh`, `host/project-id.sh`,
  `host/ssh.sh`, and core portions of `host/preflight.sh`/`host/common.sh`;
- `container/`, root `Containerfile`, core runtime/security/headless tests,
  and jailbox-only CI setup; and
- inherited `plans/`, replacing it with a JailIDE-owned active/backlog/archive
  series that describes only remaining JailIDE work.

Retain and retarget, rather than reconstruct:

- `host/editor.sh` as JailIDE editor discovery/profile/settings behavior;
- strict parser/init portions of `host/common.sh` and related validation as
  JailIDE-owned modules under a clear `host/` layout;
- `tests/unit/config-parser.sh`, `init-config.sh`,
  `editor-settings.sh`, editor-focused preflight tests, and
  `tests/e2e/editor-smoke.sh`/`editor-validate.sh`;
- JailIDE-specific public-API classification, `versions.env`, gate dispatch,
  dependency setup, tested-matrix values, source-class declarations, and CI
  inputs; and
- `AGENTS.md`, `CONTRIBUTING.md`, README, license, dependabot, and workflows,
  rewritten for the JailIDE surface.

The implementer may consolidate retained modules, but the final tree must make
configuration, editor, core-client, installation, and state ownership obvious.
No retained file may source jailbox modules or use its checkout.

Do not retain a second editable implementation of the generic installer,
packager, SemVer, or release Git mechanics. Add a JailIDE-owned toolkit
manifest, API classifier, candidate lock, and deterministic generated outputs
under the 03.2.10 contract. Until toolkit `v0.1.0` is published in 03.2.15,
generate and test from the exact recorded local candidate archive and checksum,
never either source worktree. The final published pin must reproduce identical
outputs or every affected JailIDE gate is rerun.

Generate `scripts/lint.sh` and `scripts/gen-tested-matrix.sh` from JailIDE's
own source-class and matrix declarations. Do not retain editable inherited
copies. Keep `tests/run`, `versions.env`, dependency setup, gate definitions,
and provider workflows product-owned, and prove the generated tools have the
same contract exercised by jailbox.

Initialize the pinned `jailutils` submodule established by
03.2.10.1 and package its allowlisted runtime files into JailIDE's release
artifact. Use its record codec for jailbox machine records. JailIDE retains its
required fields, decoded-value validation, command sequencing, compatibility
range, and user-facing diagnostics; it must not fork or edit common code in
this repository.

## Public identity and installation

Set these public values:

```text
display name:       JailIDE
executable:         jailide
install directory: ~/.local/share/jailide/
state root:         ~/.local/state/jailide/
profile root:       ~/.local/state/jailide/profiles/<project-id>/
first release:      v0.1.0
```

Rename the installed entrypoint to `jailide`. Generate the committed
self-contained `install.sh` and package/release frontends from JailIDE's
manifest, and test them so JailIDE touches only its own install files and
preserves state by default. Users do not install `shell-release-toolkit`.
JailIDE must never delete jailbox installation/state. Document manual removal
of legacy `~/.local/state/jailbox/editor-profiles/`; do not remove it
automatically.

Include the POSIX editor-dependency setup script owned by 03.2.13 in JailIDE's
manifest, release archive, installation, update, and uninstall inventory. It is
a product runtime input passed to jailbox, not a generated toolkit file or a
separately installed dependency.

Declare in JailIDE's canonical public API the command/flags
`jailide [--config PATH] [--editor code|codium]`, `jailide init`,
`--version`, `--help`, update, and uninstall behavior. Retarget
`scripts/public-api-diff.sh` to that surface and retain automatic pre-1.0 bump
selection through the toolkit classifier contract and JailIDE's own declared
bump policy.

## jailbox dependency boundary

Resolve one installed `jailbox` executable at invocation start and use that
exact path for `--version`, `config-schema`, `status`, `up`, and
`connection-info`. Declare a compatible jailbox version range in one JailIDE
version source, validate it before project/editor work, and give exact install
or upgrade guidance on absence/incompatibility. The installer verifies but
never installs or upgrades jailbox silently. Package metadata may express the
dependency later.

Tests must substitute a built package or prerelease installation, never call
`~/project/jailbox` or source jailbox files. Add a fake-executable harness for
portable contract tests.

## Gates and workflows

JailIDE has exactly:

```text
tests/run portable
tests/run editor
```

Retarget `tests/run` and `.github/workflows/test-gates.yml`; obtain
`scripts/lint.sh` and `scripts/gen-tested-matrix.sh` only through toolkit
generation from JailIDE-owned declarations.
Portable owns ShellCheck/syntax, parser/init/composition/client-contract units,
toolkit lock/generated-file verification, public API, package, and
install/update/uninstall lifecycle.
Editor prepares only supported positive wrapper images through the installed
jailbox artifact, then tests real pinned VS Code and VSCodium Remote SSH,
profiles/settings, proxy behavior, and launch.

PR CI runs portable and the supported editor gate. Release/canary uses both;
scheduled CI additionally tests latest compatible jailbox and its default
branch. There is no JailIDE runtime gate: jailbox owns editor-independent
container/security and negative-image cases.

## Documentation

Rewrite README for installation prerequisites, quick start, configuration,
editor precedence/matrix, profiles, bootstrap hosts, Remote SSH extension,
proxy behavior, compatible jailbox range, legacy cleanup, and troubleshooting.
Rewrite AGENTS/CONTRIBUTING to name the two gates and JailIDE module ownership.
Add MIT `LICENSE` if the inherited repository lacks it.

## Acceptance criteria

- The exact coordinated commit is verified, fast-forwarded, and recorded before
  reduction; later jailbox history is never imported wholesale.
- The final file inventory contains only JailIDE behavior plus retargeted
  repository infrastructure, with relevant Git history preserved.
- Installation, state, uninstall, API comparison, release suggestions,
  documentation, plans, and workflows consistently use JailIDE identity and
  the immutable toolkit candidate contract.
- Every jailbox interaction uses one compatible installed executable and only
  its documented machine interfaces.
- Portable and editor gates are complete, discovery-based, and cannot read the
  nested jailbox checkout.
- The nested clone remains cleanly excluded from jailbox packaging/tests until
  03.2.15 moves it.

## Non-goals

- Publishing, adding JailIDE `origin`, or moving the clone.
- Reimplementing Podman, SSH, resource identity, lifecycle, or runtime security.
- An installed or dynamically fetched shared runtime library, an editable copy
  of common code outside its submodule, an editable copied release-tool
  implementation, or automatic jailbox installation.
