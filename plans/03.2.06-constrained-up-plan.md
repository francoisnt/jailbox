# 3.2.06. Constrained up convergence

## Goal

Make `up` ensure the declared sandbox without automatically repairing,
replacing, or deleting incompatible state.

## Sequence

Implement after 03.2.02–03.2.05 and
`03-launch-core-and-up-plan.md`.

## Decision table

After full configuration and complete structural/digest inspection:

- all absent: create and start;
- compatible partial state: create missing resources and start in dependency
  order;
- orphaned ephemeral home with no development-container object: refuse without
  mutation and direct `jailbox stop` to remove the ended generation's home;
- complete healthy running state: succeed without change;
- any incompatible structure, digest, SSH state, or health failure: refuse
  without mutating pre-existing state and give directional recovery.

Reconciliation never deletes/replaces pre-existing objects. On failure roll
back only Podman resources and host SSH material created by this invocation;
preserve everything that predated it.

## Network and structure

Validate dependency attachments before mutation. Recreate a missing internal
network only when neither container survives; a home alone does not block it.
Use the actual selected subnet, including collision fallback, to derive the
live proxy URL, generated SSH session settings, and managed downloader blocks.
With a surviving network, derive from its actual subnet and require expected
attachments. Never resume a container against a recreated network.

After selecting/reusing the actual network, render fresh host SSH session
configuration before container creation and update only jailbox-managed proxy
blocks after SSH readiness. Never retain managed proxy state for a different
URL. Start dependencies in order and finish normal readiness before success.

Apply 03.2.04's recorded home mode and 03.2.05's resume validation. Preserve
read-only roots, dropped capabilities, no-new-privileges, socket isolation,
protected inputs, and proxy-only egress.

## Tests and documentation

Unit/runtime tests cover every decision outcome, dependency order, network
fallback, mode mismatches, structural failures, rollback injection, proxy
synchronization, non-mutation, and final SSH/runtime invariants.
Document explicit recovery with `jailbox stop` then `jailbox up` versus warned
`jailbox --clean` then `jailbox up`, including retained/deleted data. Update
lifecycle, image, runtime, network, and SSH modules and focused tests.

The principal implementation surfaces are `host/container-runtime.sh`,
`host/network.sh`, `host/ssh.sh`, `host/downloader-proxy.sh`, and the
`up` dispatch/preflight in `jailbox`/`host/preflight.sh`. Run
`tests/run portable` and `tests/run runtime`.

## Acceptance criteria

- Compatible absent/partial/stopped/running states converge deterministically.
- Every refusal occurs before mutation of pre-existing state.
- Failure removes only invocation-created state.
- Every consumer uses the live network proxy URL before readiness.
- Legacy or malformed policy-bearing digests never become reusable.
- An orphaned ephemeral home is a refusal state, not compatible partial state.

## Non-goals

- Automatic replacement, cleanup, lifecycle locking, or home digest gating.
