# 3.2.06. Constrained up convergence

## Intent

### Goal and sequence

Make `up` ensure the declared sandbox without automatically repairing,
replacing, or deleting incompatible state. Implement after 03.2.02–03.2.05
and `03-launch-core-and-up-plan.md`.

Complete 03.2.03's launch-guard handoff by allowing validated existing
sandboxes through convergence. Preserve the independent absence requirement
for `init` until 03.2.11 migrates it to the machine status interface.
Bare launch shares convergence and opens the editor after successful creation,
resume, or running reuse. 03.2.11 later expresses that workflow through public
CLI child processes.

### Decision table

After full configuration and complete applicable structural, digest, image,
and SSH inspection:

- all absent: create and start;
- compatible partial state: create eligible missing resources and start in
  dependency order, subject to the rules below;
- compatible stopped state: resume the existing generation, preserving SSH
  identities and its persistent or ephemeral home;
- complete healthy running state: succeed without changing the sandbox;
- orphaned complete or partial SSH-generation material without a development
  container: refuse without mutation and direct stop then up, subject to
  home-aware recovery precedence;
- orphaned ephemeral home without a development-container object: refuse under
  either requested mode and direct stop then up;
- corrupt-label home under either requested mode, with or without a development
  container: refuse with warned clean then up guidance;
- incompatible structure, digest, image currency, SSH state, or health observable
  before starting: refuse without mutating pre-existing sandbox state.

Home inspection errors are operational failures, never evidence of legacy or
corrupt metadata and never grounds for destructive recovery recommendations.
Persistent and legacy-false homes are eligible under requested false. Requested
true against either requires warned `--clean` then `up`; ephemeral-to-persistent
requires `stop` then `up`. An orphaned ephemeral home is never reusable.

When multiple incompatibilities apply, recommend recovery that resolves all of
them. Persistent-to-ephemeral mode change and corrupt home metadata outrank
concurrent digest, structure, image, SSH, or health failures because stop would
preserve the blocking home. Other incompatibilities retain stop then up guidance
when the home remains eligible. Every clean recommendation warns of permanent
home and runtime-state deletion; stop guidance explains stored persistent or
ephemeral retention. Neither recovery runs automatically.

03.2.04 has implemented home-policy checks and network-only stop guidance.
This plan integrates them with surviving containers and combined refusals.

### Image currency

The development container must have been created from the image the supplied
configuration and selected build inputs now produce. Establish this before
reuse by comparing its immutable image identity with the current wrapper build
result. The build must use the currently selected development image identity.
Apply the same identity comparison to every surviving proxy container against
the current proxy build result, including in unstamped source checkouts where
the configuration digest's version token remains `dev`.
Equal resulting identities pass this gate; different identities refuse even
when all configuration digests match. A Containerfile path or image reference
in the digest does not substitute for this check.

Superseded Containerfile bytes, build-incorporated context contents, and a
manually re-pulled `DEV_IMAGE` can produce incompatibility. A source edit
incorporated by `COPY` counts even when the project is bind-mounted at runtime.
Files ignored by the build do not by themselves require refusal. A rebuild
that produces a different identity after cache loss also refuses, even with
unchanged declared inputs; cache loss alone is not a refusal when the resulting
identity remains equal. Build or inspection errors fail operationally rather
than proving staleness.

This checks the selected build result, not reproducible builds or registry
freshness. Images are outside the preserved sandbox inventory: a refused up
may leave derived image tags pointing at newly built images. Containers,
networks, home contents, and SSH-generation material remain preserved on
compatibility refusal. Image mismatch uses stop then up guidance subject to
home-aware precedence.

Automatic refresh remains later work in
`floating-image-cache-recommendation.md`; this series does not depend on it.
This plan owns manual re-pull enforcement and tests. That recommendation owns
refresh before currency evaluation, refresh-triggered refusal, unchanged-image
reuse, offline fallback, and explicit recovery. Refresh never bypasses refusal
or automatically replaces a surviving sandbox. Attachment does not build or
evaluate image currency.

### Compatible partial states and network dependencies

Validate dependency attachments before mutation. Eligible partial states are:

- networks and/or an eligible persistent or legacy home without containers or
  orphaned SSH material: create the missing required resources;
- a surviving proxy without a development container: create a new development
  generation only when the proxy and its networks/configuration are compatible,
  no orphaned SSH material exists, and the home is eligible;
- a surviving development container: preserve its home, generation material,
  and required networks; create a missing proxy only against valid surviving
  networks without changing the development container's attachments.

Missing home or generation material beneath a development container refuses.
Create missing required networks only when neither container survives, in both
plain and egress modes; a home alone does not block creation. Never resume a
container against a recreated network or repair disconnected/unexpected
attachments. Surviving policy-bearing resources outside the requested network
mode remain subject to the complete-inventory digest and structural gates.

Derive the live proxy URL from the actual selected subnet, including collision
fallback. Use it for SSH session settings and managed downloader blocks.
03.2.05's resume validation compares stored client configuration against freshly
rendered expected settings, so derive the surviving network's actual settings
before validating. Do not overwrite stored generation files to make them pass.
Prepare new generation configuration before new development-container creation.
After SSH readiness, synchronize only jailbox-managed downloader blocks;
preserve all other home contents and finish synchronization before success.

The validated running container's own expected SSH listener permits reuse.
An unrelated listener blocks creation or resume before mutation. Start
supporting dependencies before the development container.

### Health and readiness

Success requires strict pinned SSH authentication, expected network/home and
supporting-resource attachments, read-only roots, dropped capabilities,
no-new-privileges, socket isolation, and protected read-only inputs. Egress
mode additionally requires proxy-only routing, a functioning allowlisting proxy,
and correct live session and managed downloader settings.

Required checks that fail or cannot be established fail the command; they are
not warning-only successes. Validate existing running components read-only
before mutation and newly started components before success. Checks must not
repair an incompatible sandbox or write probes into protected project paths.

External website availability remains advisory. An upstream outage alone does
not establish proxy failure; arbitrary DNS or transport failure is not proof
of policy rejection or isolation. Required proxy checks must distinguish those
outcomes from evidence of readiness and allowlist enforcement.

03.2.09 owns integrating applicable read-only health checks into its attachment
validator and verifying them through the shared matrix. Image construction and
managed-home synchronization remain exclusive to up.

### Refusal and startup failure

Compatibility refusal precedes mutation of pre-existing sandbox state. Complete
persistent structure, policy, generation, and observable running-health checks
before creating resources or starting surviving containers.

Failure after an allowed create/start is distinct: readiness of a stopped
container cannot be proved until it starts. Return failure and preserve all
surviving objects and their generation material. Never automatically stop or
delete a pre-existing container, including one this invocation started. Report
its observed final state: it may remain running or have exited. Do not promise
restoration of process state, tmpfs, or startup writes to the home. Managed
proxy synchronization may also have completed before a later failure; unrelated
home contents remain protected.

Roll back only invocation-created Podman resources and host launch material,
in dependency order. Retain a newly created dependency while a surviving
container still needs it, and retain authentication material if dependent
container removal fails. Report retained resources, cleanup failures, and
explicit recovery rather than claiming complete rollback. Forced termination
need not execute rollback; resulting leftovers obey the same inspection and
explicit recovery rules. 03.2.07 owns independently constructed failed-resume
and dependency-safe rollback coverage in its shared matrix.

### Acceptance criteria

- Public-CLI absent, eligible partial, stopped, and running states reach the
  declared outcomes; incompatible containers receive the applicable refusal.
- Running reuse preserves container identities, generation files, and healthy
  managed settings. Stopped resume preserves SSH identities and ephemeral-home
  contents as well as persistent homes. Bare launch opens the editor only
  after success, including reuse; init retains its independent absence guard.
- Own 03.2.02's complete-inventory digest integration: inspect both containers
  and all plain/internal/external project networks, including resources outside
  the requested mode. Missing, malformed, inconsistent, and mismatched digests
  refuse without mutation; legacy metadata never becomes reusable.
- Own 03.2.05's public-CLI no-op/resume integration: validate complete SSH
  generations, attachments, and supporting resources before mutation/start.
  Running reuse validates SSH readiness. Damaged SSH state refuses without
  repair and preserves existing objects and files.
- Own 03.2.05's complete/partial orphan refusal and broader rollback integration:
  execute stop then up recovery, preserve unrelated runtime files, remove new
  dependent containers before their authentication material, and report cleanup
  failures and required retained dependencies.
- Pre-mutation refusal snapshots remain unchanged. Readiness failure after
  starting a surviving container and failure after creating a missing dependency
  preserve surviving identities and apply the documented post-start contract.
  Report final state and verify explicit recovery, including home retention.
- Own 03.2.04's combined-home refusal integration: under both requested modes,
  with and without containers, test corrupt/legacy/mode-change/orphan homes,
  combined digest and structural failures, inspection errors, non-mutation,
  and execution of recovery that resolves all applicable refusals. Never infer
  mode on inspection failure; warn for destructive recovery.
- Test plain and egress missing-network refusals with surviving containers and
  eligible partial creation without attachment repair. Collision fallback
  reaches generated SSH settings before readiness and managed blocks before
  success. Synchronization preserves non-jailbox contents, completing 03.2.04's
  reused-home content handoff.
- The validated running container's listener permits reuse; an unrelated
  listener blocks creation/resume before mutation.
- Required SSH/runtime/proxy failures return nonzero; external availability
  warnings alone do not. Tests distinguish denial from failed DNS/transport.
- Changed Containerfile, incorporated build-context contents, and manual re-pull
  fixtures producing a different dev/wrapper result refuse despite matching
  digests. Unchanged cached builds permit reuse. Cache-loss tests apply the
  same identity rule, including different results with unchanged declarations.
  The different-result fixture must establish that the rebuilt identity actually
  differs before asserting refusal; equal identities cannot satisfy that case.
  Changed `container/tinyproxy/` content producing a different proxy image also
  refuses reuse of a surviving proxy under an unchanged `dev` digest.
  Sandbox snapshots remain unchanged despite image-tag updates.

### Non-goals

Automatic replacement or cleanup of incompatible state, lifecycle locking,
home digest gating, reproducible builds, automatic registry refresh, or image
currency enforcement during attachment.
