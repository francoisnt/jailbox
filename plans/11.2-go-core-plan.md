# 11.2. Go core

## Intent

Replace the Bash core with the Go core program, so `jailcore` runs without
Bash. Implement after `11.1-go-frontend-plan.md`, which splits out the public
`jailcore` interface and moves the frontend to Go. This series does not depend
on `12-go-vm-frontend-plan.md`.

The goal is less complexity, not fewer lines: typed Podman data instead of
template strings, explicit error handling and rollback instead of errexit and
trap discipline, and in-process test doubles instead of command-line shims.

### Contract to preserve

- `jailcore` commands, `JAILBOX_CONFIG_*` configuration, output framing,
  exit statuses, diagnostics that callers rely on, and recovery scope.
- Resource names, labels, and host state layout. The Go core inspects, refuses
  to reuse, stops, and cleans resources and state created by earlier releases,
  as the current core does.
- Every security invariant in `AGENTS.md` and the README threat model.
- The configuration digest needs no cross-release byte compatibility, because
  it already includes the exact version.

No new features or behavior changes. The installer stays Bash 3.2, and
container-side scripts stay POSIX `sh`.

### Members

Implement in order. Each member moves one area completely, removes the Bash
modules it replaces, and leaves all five gates passing:

1. `11.2.1-go-core-configuration-plan.md`: configuration, project identity,
   path policy, and the digest.
2. `11.2.2-go-core-resources-plan.md`: Podman access and resources.
3. `11.2.3-go-core-lifecycle-plan.md`: lifecycle and remaining commands; the
   Bash core is removed.
4. `11.2.4-public-interface-plan.md`: the public interface declared in Go and
   release versioning from it.
5. `11.2.5-go-core-test-harness-plan.md`: test doubles and matrix fault
   injection for the Go core.

### Acceptance

All five gates pass after each member, with the full lifecycle matrix. Core
coverage is moved, not dropped. A test creates resources with the most recent
released core and recovers them with the new one.

## Implementation detail

Choose the Bash-Go boundary per member. Keep it private, as the forwarding
helpers do today, and remove each crossing when its last caller moves. Avoid
long-lived duplicate implementations of the same behavior.
