# 3.2.02. Version-bound configuration digest

## Goal

Use one digest as the compatibility contract for every independently surviving
policy-bearing resource.

## Sequence

Implement after `03.2.01-release-version-plan.md` and before ownership-label
removal. It depends on launch/image selection from
`03-launch-core-and-up-plan.md`.

## Canonical digest

SHA-256 hash this versioned stream of TAB-separated fields on
newline-terminated records, matching the record style of 03.2.08's
`config-schema`:

```text
jailbox-config-digest-v1
jailbox-version<TAB>EXACT_VERSION
scalar<TAB>KEY<TAB>VALUE
array<TAB>KEY<TAB>COUNT
value<TAB>ITEM
containerfile<TAB>none
```

Emit one scalar/array record per final validated machine configuration key —
the members of `CONFIG_SCALAR_KEYS` and `CONFIG_ARRAY_KEYS`; each array item
follows its `array` record as one `value` record. Replace the last record
with `containerfile<TAB>path<TAB>CANONICAL_PATH` when selected, or
`containerfile<TAB>missing` when attach observes that an explicit or
implicit selection disappeared. `DEV_IMAGE` emits `none` without inspecting
candidate/configured Containerfiles. The ordinary `DEV_CONTAINERFILE` scalar
remains the configured spelling (empty under implicit discovery); discovery
never mutates it.

Counts are canonical unsigned decimal. Empty arrays have count zero, an
empty scalar keeps its trailing field separator so the empty value remains an
explicit field, and every item gets a `value` record. `COUNT` is always the
number of `value` records that follow it, so for a set-valued key it is the
post-deduplication member count. Every encoded field is a validated
control-character-free value — configuration values by 03.1's
rejection rule, the version and record tags by construction, and the
Containerfile record's path because it derives from a validated configured
value or a fixed discovered filename — so TAB and newline framing is
unambiguous; a coverage assertion fails if any encoded field ever contains a
control character. The encoding needs no cross-release stability: the exact
version is hashed in, so a future encoding change is an ordinary digest
mismatch, and golden vectors pin only within-release determinism and tool
portability. Require `sha256sum` or `shasum -a 256` and normalize 64
lowercase hex.

Do not include config-file identity as an input of its own, nor
source/provenance, editor discovery, bootstrap results, resource names, or
launch-derived state. The frontend's config file path reaches the digest only
when it is anchored into `READONLY_PATHS`, where it is hashed as an ordinary
configured path because it names a file the sandbox must not be able to
rewrite. Containerfile path identity is included, not its bytes.
Frontend-only keys (`FRONTEND_SCALAR_KEYS`) never reach the machine
environment and are never hashed; the editor choice they express already
reaches the digest through the bootstrap hosts the frontend composes into
`EGRESS_ALLOW`. Use the same trusted selector/discovery order as image
construction without building/inspecting an image. Launch gives its specific
missing-input error; attach emits `missing` and gives ordinary stale-sandbox
guidance. A coverage gate fails when any machine configuration key lacks
exactly one canonical record.

Emit keys in declaration order and preserve array order by default. Only
`EGRESS_ALLOW` is set-valued: serialize bytewise `LC_ALL=C` sorted unique
members. Keep it in one `DIGEST_SET_ARRAY_KEYS` declaration which portable
coverage proves contains only members of `CONFIG_ARRAY_KEYS`. Path-array
order remains significant because mount precedence may matter; future keys
over-invalidate until explicitly proven set-valued.

## Compatibility

Record `jailbox.config-digest` on development container, proxy container, and
network. Before reuse, partial convergence, or attachment, every existing
policy-bearing resource must carry one matching current digest; missing,
malformed, inconsistent, or mismatched labels refuse before mutation. Validate
the normalized value before creation/comparison and compute after read-only
Containerfile classification but before lifecycle mutation. The home
volume is excluded and uses 03.2.04 lifecycle metadata.

The home is the deliberate exception because it has no immutable
security-relevant creation settings; current security comes from container
mount/runtime policy. Version binding is deliberately conservative: it prevents
a new release from resuming containers whose immutable Podman settings were
created by older hardening rules.

## Tests and migration

Golden vectors cover order, boundaries, empty/unset/default values, array items
including commas, version and Containerfile changes, tool portability, and
key coverage. Existing unlabeled resources are incompatible and receive
explicit stop/up or warned clean/up guidance.

README documents the remaining content-behind-reference gaps: mutable or
re-pulled `DEV_IMAGE`, edited Containerfile bytes, and changed build-context
contents are not observed until relaunch. Exact jailbox version now covers
implementation-version skew. Equal final policy is equivalent regardless of
the frontend config file's formatting. An in-project file's path is not
formatting: it is anchored into `READONLY_PATHS` and therefore hashed, so the
same content selected at a different in-project path is a different sandbox.
An out-of-project selection contributes no anchor.

## Acceptance criteria

- Exact version, effective public values, and Containerfile identity alone
  determine the digest.
- All three resource kinds carry the label and the complete-set comparison
  rejects every missing/inconsistent/current mismatch before mutation/attach.
- Home persistence remains independent of the digest.
- Egress reordering is stable; path-array reordering changes the digest.
- Source and installed versions produce different digests.

## Non-goals

- Ownership proof, image/Containerfile/build-context content hashing,
  current-policy diagnosis without supplied configuration, or an independent
  protocol version.
