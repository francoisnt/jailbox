# 3.2.09. `connection-info`, shared validator, and `doctor`

## Goal

Provide one complete read-only attachment validator, a stable machine schema
for SSH consumers, and detailed non-mutating human diagnosis.

## Sequence

Implement after 03.2.02–03.2.08. Plans 5 and 6 and JailIDE plan 03.2.13 call
the shared validator rather than defining attach compatibility themselves.

## Shared attachment validator

Refactor the read-only checks into a host module owned with lifecycle/runtime
state (normally `host/container-runtime.sh`, with SSH checks delegated to
`host/ssh.sh` and network checks to `host/network.sh`). It accepts the final
validated environment policy and checks, before transport:

- exact derived resource names and the exhaustive required resource set;
- a running, SSH-responsive development container;
- matching current `jailbox.config-digest` labels on every required
  development container, proxy container, and network;
- internally consistent container/network/home attachments and valid home-mode
  metadata;
- complete host and mounted SSH-generation material, ownership, modes, file
  types, pinned identity, and generated client configuration; and
- when filtering is enabled, the required running proxy and live network URL.

It creates, starts, stops, repairs, replaces, labels, or removes nothing.
Failures distinguish absence, stopped/unresponsive state, legacy or
inconsistent digest, structural damage, SSH damage, and proxy failure, and give
the owning `stop`/`up` or warned `--clean`/`up` recovery. Exact names,
not `jailbox.project`, identify resources.

## `connection-info` schema

`jailbox connection-info` loads and validates the complete environment
configuration, computes the current digest, invokes the shared validator, and
on success emits these fixed-order tab-separated records:

```text
ssh_config<TAB>ENCODED_ABSOLUTE_PATH
ssh_host<TAB>ENCODED_HOST_ALIAS
remote_path<TAB>ENCODED_ABSOLUTE_PATH
project_id<TAB>ENCODED_PROJECT_ID
proxy_url<TAB>ENCODED_PROXY_URL_OR_EMPTY
```

Values use unwrapped RFC 4648 Base64. Add one shared host codec, extracted into
`jailutils` by 03.2.10.1 and reused by plan 5, that selects portable GNU or
BSD/macOS encoding/decoding and removes line wrapping without changing bytes.
Keep framing and field-name grammar independent of this command: callers supply
allowed and required field sets and perform all decoded-value validation. The
codec rejects malformed Base64, malformed framing, and duplicate records while
returning unknown valid fields so the caller can apply its documented policy.
`connection-info` ignores unknown valid fields but rejects missing required
fields and invalid decoded paths, aliases, project IDs, or proxy URLs.

`proxy_url` is required: live collision-fallback-aware internal URL when
filtering, empty otherwise. Do not expose allowlists, private-key paths,
known-host contents, container names, or raw configuration. jailbox alone
provides remote `NO_PROXY` and `no_proxy` in generated SSH configuration.
The jailbox release version governs this schema.

Add the command to `CLI_FLAGS_WITHOUT_VALUES`, `CLI_HELP`, dispatch,
`scripts/public-api-diff.sh`, usage, and the configuration-consuming preflight
class. It needs Podman, SSH, SHA-256, Base64, and project identity, but no
editor, config file, or `cksum`.

## `doctor`

Keep `doctor` configuration-independent and human-facing. It reports the
one-word status plus every derived Podman resource, runtime state, label
presence/consistency, home lifecycle metadata, SSH presence/permissions/
consistency, live network subnet, proxy state, and precise recovery. Without
current configuration it never claims a consistent recorded digest matches
current policy. Its stdout is not a stable machine schema. Every clean
recommendation warns of home and runtime-state deletion.

Remove any editor/config-file-specific doctor branch. Reuse inspection
primitives with the validator but do not make doctor invoke configuration
loading or mutation.

## Security invariants

All checks precede attachment and preserve read-only roots, dropped
capabilities, no-new-privileges, socket isolation, proxy-only egress, and strict
host-key state. Machine output contains connection metadata but no secret.

## Tests and documentation

- Unit-test each validator decision and prove no Podman/host-state mutation.
- In runtime tests, feed every 03.2.07 adversarial state through
  `connection-info`, plans 5/6 consumers, and doctor.
- Golden-test record order, required empty proxy, collision fallback, unknown
  forward-compatible fields, malformed/duplicate/missing fields, and secret
  absence.
- Exercise GNU and BSD/macOS Base64 command behaviors in portable fixtures,
  and prove different caller-supplied schemas use the same codec without
  embedded `connection-info` field names or value policy.
- Document stable machine output separately from unstable human doctor output.

Run `tests/run portable` and `tests/run runtime`.

## Acceptance criteria

- All attachment consumers invoke one validator covering every policy-bearing
  resource and SSH/network dependency.
- Connection-info emits the exact required schema only after validation, with a
  live proxy URL or required empty value and no secret.
- Base64 framing round-trips on GNU and BSD/macOS hosts.
- Doctor gives complete non-mutating recovery diagnosis without claiming a
  policy comparison it did not perform.

## Non-goals

- Lifecycle mutation, a second validator, exposing the allowlist, or making
  doctor a stable automation interface.
