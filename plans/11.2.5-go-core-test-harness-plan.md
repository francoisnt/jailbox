# 11.2.5. Go core test harness

## Intent

Last member of `11.2-go-core-plan.md`. Replace the shell scaffolding that
fakes Podman and SSH for core, and the matrix's text-matched fault points,
with mechanisms built for the Go core.

- Core's unit coverage runs in Go against an in-process engine double behind
  the interface from `11.2.2-go-core-resources-plan.md`.
- The lifecycle matrix keeps running the real `jailcore` against real Podman,
  with the same interruption cases, contracts, and cross-shard coverage proof.
  Core names its fault points, and a test build triggers them, instead of
  shims on `PATH` matching command lines as text.
- Fault hooks are compiled out of release builds, and release validation
  checks that they are absent.
- Lifecycle membership still derives from the declared public category, and a
  lifecycle command without a validated contract still fails.

Remove what the new mechanisms replace once their suites move:
`tests/lib/lifecycle-fault.sh`, `tests/lib/convergence-fixture.sh`, and
`tests/fixtures/convergence/`. Keep frontend, shell-behavior, and
container-side tests.

## Implementation detail

Go build tags suit the test-only hooks. Preserve the matrix's existing case
names where practical so coverage proofs stay comparable.
