# 3.2.11.3. Make allowlist reuse agree with the digest

## Intent

### Goal and place in the sequence

Read the two umbrella plans first. Implement after 03.2.11.2 and before the
public frontend switchover in 03.2.11.4. Make the core proxy renderer and reuse
comparison agree with the digest's existing set semantics.

### Required behavior

Reordering or repeating otherwise identical allowed hosts permits reuse of a
healthy sandbox. The canonical host set hashed as `EGRESS_ALLOW` and the host
set represented by the proxy filter must agree once frontend composition is
activated. An actual host-set change still refuses reuse with explicit stop
and relaunch guidance; do not weaken health, digest, or structural checks.

Migrate the order-sensitive rendering/comparison in `effective_egress_allowlist`
and `validate_proxy_configuration` in `host/network.sh`. Until 03.2.11.4
activates frontend composition, preserve the current editor bootstrap behavior.
The receiving switchover plan owns removal of that core editor dependency;
this step must not break existing editor launches by removing it early.

### Verification and handoff

- Add regressions showing equivalent reordered/repeated host sets render and
  validate consistently, including the currently automatic editor hosts.
- Verify changed hosts still fail and unfiltered mode remains unfiltered.
- Run `tests/run portable`, runtime and matrix when their prerequisites are
  available, and editor for affected editor integration; report unavailable
  gates rather than treating partial checks as passing.
- 03.2.11.4 removes core bootstrap composition and `EDITOR_BIN` dependence,
  using the prepared frontend contribution instead. It must prove that the
  digest and rendered filter use the same final policy for machine and frontend
  paths, with no stop/relaunch for unchanged composed policy.
- 03.2.11.5 completes the cross-path integration cases: duplicate/reordered
  inputs, editor/headless switches, and equivalent versus changed policy for
  `connection-info`, `exec`, and `shell` after filtered editor launch.

### Acceptance criteria

Proxy comparison no longer refuses equivalent host sets merely because of
order or repetition. Changed policy still refuses. Current editor behavior
continues to work until the explicitly owned switchover.

## Implementation detail

Use a consistent effective-host representation for rendering and comparison.
The digest already treats `EGRESS_ALLOW` as a set; do not change ordered
`READONLY_PATHS` semantics or introduce another policy owner. This is a
bounded network-policy correction, not the frontend/core directory migration.
