# 3.2.11. Editor frontend layering

## Intent

### Goal

Restructure the human editor workflow into a frontend layer that consumes
jailbox's machine interface exclusively through the public CLI, making bare
`jailbox` the reference consumer of environment configuration, `up`, and
`connection-info`.

Read ARCHITECTURE.md for an explanation of the lifecycle, boundaries, testing
strategy, and terminology before implementing this series. It distinguishes
current behavior from the intended frontend; the numbered plans own the
implementation contract.

### Observable result

- One installed executable and one repository contain both layers. Frontend
  files reside in `host/frontend/`, machine modules in `host/core/`, and shared
  declarations remain in `host/public-api.sh`.
- Bare launch is a file-driven editor workflow calling public `up` and then
  `connection-info` with identical composed policy. The frontend neither calls
  private core helpers nor inspects sandbox resources.
- Frontend configuration comes from the selected file. File `EDITOR` selects
  the editor; when unset or empty, discover Codium then Code. No environment
  variable overrides that selection.
- `--no-editor` preserves the file-driven headless workflow. Machine commands
  are environment-only. Explicit `--config PATH validate` composes headless
  file policy and delegates to core validation. Init is local and state-independent.
- Editor preflight precedes machine calls; a child failure or invalid connection
  stream prevents editor launch. Profile publication preserves accepted data
  and prior settings on failure.
- File anchors and editor bootstrap hosts participate in effective policy,
  its digest, and actual mounts/filtering. Equivalent policy permits healthy
  reuse; actual changes require explicit recovery, never automatic replacement.
- Frontend commands stay outside the core lifecycle matrix and have their own
  delegation/composition tests. The real editor gate proves public-CLI integration.

### Security invariants

Development/proxy hardening, socket isolation, project-external runtime
state, proxy-only egress, and strict pinned SSH remain core-enforced and are
not reimplemented in the frontend. The frontend read-only anchors every
in-project policy input it consumes, matching the existing config-anchor
contract. It trusts project files at invocation start and does not monitor
later host edits; this limit stays in the threat model. Remote session
`HTTP_PROXY`/`HTTPS_PROXY`/`NO_PROXY` variables remain exclusively
jailbox-generated SSH session behavior; the egress allowlist is never copied
into editor settings.

### Editor packages

Editor-server runtime packages remain in core `container/setup.sh` as part of
the generic attached-development wrapper contract. No caller setup-script
mechanism exists; users customize images through their Containerfile.

### Non-goals

- A repository split, second installed executable, Go implementation, TOML

- Automatic recovery, direct state inspection, Git-integrity monitoring,
  credential management, scheduling, or editor support outside the tested
  matrix.

## Implementation detail

Within the required directories, choose modules that keep the public CLI calls
easy to audit, and expose no private core lifecycle helpers to the frontend.
The test-fixture mechanisms named above are guidance: reuse the
existing test harnesses and 03.2.07's shared lifecycle matrix rather than
adding parallel frameworks.

Use a consistent representation of the effective host set for proxy rendering
and reuse comparison. Keep JSON string encoding and connection-record parsing
in focused, format-specific helpers; shell quoting is not JSON encoding. Pass
local process arguments as arrays and reuse the same settings interpretation
for generation verification and later inspection. These mechanisms support the
contracts above without introducing a general serialization framework.

Concentrate file parsing, editor selection, and bootstrap-host composition in
their frontend owner. Reuse core policy through public commands rather than
copying lifecycle or attachment decisions into frontend helpers. Shared public
declarations remain the source of interface membership. Share test setup and
recording where useful, but specify expected child-command behavior and policy
outcomes independently of the production composition being tested. Evaluate
simplification by fewer policy owners and dependencies, not by a line-count
target or an additional abstraction layer.
