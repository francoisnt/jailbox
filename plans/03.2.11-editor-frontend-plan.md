# 3.2.11. Editor frontend layering

## Intent

### Goal

Restructure the human editor workflow into a frontend layer that consumes
jailbox's machine interface exclusively through the public CLI, making bare
`jailbox` the reference consumer of environment configuration, `up`, and
`connection-info`.

### Sequence

Implement after 03.2.01–03.2.09. This plan replaces the archived split-era
plans numbered 03.2.11 through 03.2.15; the deferral is recorded in
`repository-split-rationale.md`.

### Module ownership and boundary

Gather frontend behavior in a frontend layer, absorbing `host/editor.sh`
and the strict config-file parser retained by 03.1:

- `jailbox.conf` discovery, `--config` selection, strict parsing, and `init`;
- editor binary/version and Remote SSH extension discovery and validation;
- isolated profile path/settings generation under
  `~/.local/state/jailbox/editor-profiles/`;
- deterministic environment composition and machine-command invocation; and
- connection-record parsing and editor launch.

The frontend reaches core only by executing the public CLI as child
processes. It never calls lifecycle, network, SSH, image, or identity
functions in-process, never invokes Podman, and never reads SSH or runtime
state files directly; `connection-info` is its sole source of connection
data. Enforce this with a boundary check in `scripts/lint.sh` or a portable
test that fails when the frontend module references non-public core functions
or core state paths.

With this plan, machine commands stop reading `jailbox.conf`: delete the 03.1
temporary adapter fallback from `up`, `exec`, `shell`, and `connection-info`.
Core also stops anchoring config files, because it can no longer resolve
them: remove `DEFAULT_CONFIG_INPUT`, `SELECTED_CONFIG_INPUT`, and
`DEFAULT_CONFIG_PRESENT` from `host/common.sh` and their automatic-input
handling from `finalize_effective_readonly_paths` in
`host/container-runtime.sh`, leaving `SELECTED_DEV_CONTAINERFILE_INPUT` in
place because the Containerfile remains a core input. The frontend's
`READONLY_PATHS` anchor replaces the removed automatic protection, so the
protection itself is unchanged; only the layer that declares it moves.

The strict parser survives as frontend code and the file remains the
frontend's permanent human surface. Environment callers are unaffected. The
parser keeps both of its current value rules — no whitespace and no shell
metacharacters — and adds rejection of ASCII control characters (bytes
0x01–0x1F and 0x7F). The combined rule rejects a strict superset of what
03.1's environment contract rejects, so every value the file admits is
already a legal environment value and the file-to-environment mapping is
byte-clean by construction. Because the existing whitespace rule already
covers TAB and the newline family, the addition newly rejects only the
remaining control bytes.

### Command surface

Bare `jailbox` is the human editor launch. `jailbox --no-editor` performs the
same file-driven composition and `up` invocation but skips editor discovery,
bootstrap-host composition, and editor launch, preserving today's headless
`jailbox up` file workflow; the machine `up` command itself is environment-
only. `init` and `--config` keep their current semantics under frontend
ownership.

Declare `--no-editor` as a non-lifecycle frontend command in
`host/public-api.sh`, with the required help and handler mappings. It delegates
sandbox lifecycle operations to `up`; verify its composition separately from
`up`'s lifecycle matrix coverage. Frontend-only file keys
already live in their own `FRONTEND_SCALAR_KEYS` class there, separate from
`CONFIG_SCALAR_KEYS`/`CONFIG_ARRAY_KEYS`; preserve that separation so
`config-schema` never emits them while `scripts/public-api-diff.sh` still
covers them. The generated public-API comparison must classify every
declaration this plan adds, removes, or changes — `--no-editor` added;
`ssh-config` and the temporary `up` file fallback removed — under 03.2.01's
bump policy. The config-file value grammar tightens as well; because the
comparison diffs declaration names rather than validation rules, that change
is classified by the review 03.2.01 requires, not by the generated diff.

### Launch sequence

Bare `jailbox` performs these ordered steps:

1. Canonicalize the project and default/selected configuration paths under
   the existing symlink rules; the default `jailbox.conf` anchor is required
   even when `--config` selects another file.
2. Parse the selected file with the strict parser. File `EDITOR` is
   frontend-only state and is never exported to core.
3. Resolve the editor by precedence `JAILBOX_EDITOR`, then file `EDITOR`,
   then `codium` when available, then `code`, and validate the supported
   binary/version and Remote SSH extension before any lifecycle mutation.
4. Compose the final machine environment: map file keys to bare
   `JAILBOX_CONFIG_<KEY>` scalars and contiguous indexed array members;
   append the selected editor's bootstrap destinations to `EGRESS_ALLOW`;
   append the default and any distinct selected in-project config file to
   `READONLY_PATHS`; retain first occurrences and drop later byte-identical
   duplicates. Construct a fresh child environment so inherited
   `JAILBOX_CONFIG_*` variables cannot alter policy; only parsed and
   composed declarations are exported.
5. Invoke `jailbox up` as a child process with exactly that environment.
6. If and only if `up` succeeds, invoke `jailbox connection-info` as a child
   process with the byte-identical environment.
7. Strictly parse the NUL-delimited records defined by 03.2.09: require one
   each of `ssh_config`, `ssh_host`, `remote_path`, `project_id`, and
   `proxy_url` in the documented order; reject duplicates, malformed or
   unterminated records, and missing fields; ignore valid trailing future
   fields.
8. Generate isolated editor settings — set editor `http.proxy` exactly when
   `proxy_url` is non-empty and omit it otherwise — and launch Remote SSH at
   the reported host and path.

Generated settings must be valid JSON and preserve each accepted connection
value exactly after JSON decoding, including quotes and backslashes in paths.
Settings inspection must recognize those same decoded values. Invalid input
must fail before editor launch rather than publish unusable settings.

Never infer success from diagnostics or continue after either child command
fails. The frontend never calls `stop` or `--clean` automatically; refusals
surface core's directional recovery guidance unchanged. Editor choice changes
bootstrap hosts and therefore the digest; switching editors against existing
resources refuses, and the documented recovery is `jailbox stop` then a fresh
launch. Because `--no-editor` skips bootstrap-host composition, switching
between bare `jailbox` and `--no-editor` against an existing filtered sandbox
is the same digest-mismatch refusal in either direction, with the same
`stop` + relaunch recovery; unfiltered sandboxes compose no bootstrap hosts
and switch freely. Selecting a different in-project file with `--config`
likewise changes `READONLY_PATHS` and therefore the digest, because the
anchor names the file the sandbox must not be able to rewrite; that switch
refuses with the same `stop` and relaunch recovery. An out-of-project
selection contributes no anchor and does not change the digest on that
account.

### `init` and `ssh-config`

`init` keeps its template and no-overwrite behavior but gates on machine
state by running `jailbox status` and requiring stdout to be exactly
`absent`, per 03.2.08, instead of inspecting containers itself.
Complete 03.2.06's retained init-guard migration: replace `run_init`'s call to
`require_sandbox_absent` in `jailbox` with the frontend status gate and remove
the obsolete helper from `host/container-runtime.sh`.

`init` also seeds advisory protection suggestions: it detects existing
project paths from a documented fixed candidate set — such as `.env`, Git
hooks and policy files, and CI workflow directories — and writes each
detected path into the created file as a commented-out `READONLY_PATHS`
suggestion, in stable documented order. Absent candidates are skipped
without stubs, nothing is enabled, and the created effective policy remains
the minimal `READONLY_PATHS=`. The interactive and flag-driven
initialization design remains backlog work.

Delete `ssh-config`: remove its `CLI_OTHER_COMMANDS` and `CLI_HELP` entries,
its `CLI_COMMAND_HANDLERS` mapping in `host/common.sh`, `run_ssh_config` in
`jailbox`, and `print_ssh_config_instructions` from `host/ssh.sh`. Machine
clients use `connection-info`, and `doctor` already carries the
editor-agnostic connection instructions under 03.2.09's obligation, so this
deletion removes no capability; README supplies the editor setting name
pointing at the path doctor reports. Remove doctor's editor- and
config-file-specific branches here too: editor diagnosis belongs to the layer
that resolves the editor, and core `doctor` reports no editor state after this
plan. Its `CLI_HELP` description in `host/public-api.sh` narrows to match; the
description is user-visible text rather than a declared flag, so 03.2.01's
review classifies the change.

Editor validation therefore carries the diagnostic obligation that doctor's
removed branches used to serve. A validation refusal must name every
requirement it found unmet and the resolved editor together with the
precedence step that selected it, so a user can correct the setup from one
refusal instead of discovering the next problem on the next launch. Because
validation precedes any lifecycle mutation, a refused launch leaves no
resources behind and is safe to repeat as a diagnostic.

Editor validation covers host-side binary/version and extension requirements;
it does not diagnose the selected image's compatibility with that editor.
Remove `warn_if_alpine_dev_image_with_vscode` from `host/dev-image.sh` and
its `run_launch` hook in `jailbox`, including `bring_up_sandbox`'s
`pre_build_hook` plumbing. Remove the Alpine/VS Code warning branch in
`doctor_jailbox` in `host/container-runtime.sh` together with the other
editor-specific diagnosis. Neither core nor the frontend emits an automatic
Alpine/VS Code compatibility warning. README retains the explicit requirement
to use VSCodium for Alpine images, the troubleshooting guidance, and the
supported editor/image matrix. The frontend's preflight success certifies the
host editor prerequisites only, not remote image compatibility.

### Editor packages

Editor-server runtime packages remain in core `container/setup.sh` as part of
the generic attached-development wrapper contract. No caller setup-script
mechanism exists; users customize images through their Containerfile.

### Security invariants

Development/proxy hardening, socket isolation, project-external runtime
state, proxy-only egress, and strict pinned SSH remain core-enforced and are
not reimplemented in the frontend. The frontend read-only anchors every
in-project policy input it consumes, matching the existing config-anchor
contract. It trusts project files at invocation start and does not monitor
later host edits; this limit stays in the threat model. Remote session
`HTTP_PROXY`/`HTTPS_PROXY`/`NO_PROXY` variables remain exclusively
jailbox-generated SSH session behavior; the egress allowlist is never copied
into editor settings.

### Tests and documentation

- This plan owns 03.2.02's composition integration tests: compare the canonical
  host set hashed as `EGRESS_ALLOW` with the set represented by the rendered
  proxy filter, including editor-added hosts, duplicate/reordered inputs,
  editor switches, and filtered headless launches. Verify unfiltered launches
  compose no bootstrap hosts. Verify default and selected in-project config
  anchors reach the hashed `READONLY_PATHS` and read-only mounts, while an
  out-of-project selection adds no anchor.
- Verify that reordering or repeating otherwise identical allowed hosts permits
  reuse of a healthy sandbox through both machine and frontend launch paths.
  Digest equivalence and proxy validation must agree; an actual change to the
  effective host set still requires explicit stop and relaunch. Migrate
  `effective_egress_allowlist` and `validate_proxy_configuration` in
  `host/network.sh` so their order-sensitive rendering/comparison cannot reject
  an equivalent set. Include automatically added editor hosts in this check.
- Verify JSON round trips for accepted connection values, including paths with
  spaces, quotes, and backslashes, and verify settings inspection agrees.
  Replace the raw JSON interpolation and literal-text settings check currently
  in `host/editor.sh` as that behavior moves into the frontend.
- Portable tests stub the machine commands to record exact child-command
  order, environment construction (a snapshot of variable names and order,
  without values), composition deduplication, control-character rejection in
  file values, connection-record parsing including malformed NUL framing,
  `--no-editor` behavior, and refusal to launch an editor after preflight,
  `up`, or `connection-info` failure.
- Validation-refusal tests assert that a refusal enumerates every editor
  requirement it found unmet, names the resolved editor and the precedence
  step that selected it, and runs before any machine command.
- Verify removal of the image/editor launch hook and doctor's Alpine/VS Code
  warning leaves no editor-dependent image probe in core and introduces no
  frontend access to image internals. Existing Alpine/VSCodium editor coverage
  remains in the editor gate; README continues to identify Alpine/VS Code as
  unsupported.
- `init` tests cover candidate detection, stable suggestion ordering,
  skipped absent candidates, and that every suggestion is commented out and
  the effective created policy is unchanged.
- The boundary check fails on any frontend reference to non-public core
  functions or state paths.
- The editor gate continues covering pinned VS Code/VSCodium versions,
  Remote SSH validation, profiles, filtered/unfiltered/collision-fallback
  proxy settings, first launch, reopen, stopped resume, and — against a
  filtered sandbox — both editor-switch and bare/`--no-editor` switch
  refusals with their recovery; it now doubles as the machine-interface
  integration test, since the frontend reaches core only through the CLI.
- README documents that bare `jailbox` composes and invokes `up` and
  `connection-info` exactly as an external orchestrator would, regenerates the
  command reference for `--no-editor` and the removed `ssh-config`, points
  readers at `doctor` for connection instructions and gives the editor
  setting name to pair with the path it reports, states that editor problems
  now surface as launch refusals rather than in `doctor`, keeps editor
  precedence and bootstrap-host documentation, and documents that switching
  editors, switching between bare and `--no-editor` launches of a filtered
  sandbox, or selecting a different in-project `--config` file requires
  `jailbox stop` first.
- This plan owns the charter's caller-serialization documentation. Machine
  guidance requires orchestrators to serialize lifecycle mutations per project
  and exclude them throughout dependent sequences such as `up` then
  `connection-info`. Frontend guidance explains that concurrent launches,
  stops, and cleans for one project are unsupported: the frontend does not
  lock the sequence or exclude another terminal or process. Review both
  sections for these limits without implying an atomic transaction or
  protection throughout a long-lived editor session.

Run `tests/run portable`, `tests/run runtime`, and `tests/run editor`.

### Consumer compatibility and durable documentation

This plan owns the charter and 03.2.08/09 consumer verification handoffs.
Extend portable frontend fixtures and a small external automation consumer
fixture to exercise public version discovery, compatible range selection,
schema discovery, environment composition and connection parsing. Range
selection belongs to the consumer fixture; do not add a frontend self-version
pin or require the frontend to discover declarations it already knows. Test
valid additional schema keys and trailing connection fields, missing required
keys, unknown types, duplicate/malformed/truncated records, incompatible
versions, and failed child commands with plausible success stdout. Never launch
an editor or attach after any failed command or malformed result.

Run the automation fixture against the real CLI in the runtime gate and the
real frontend in the editor gate. Portable fixtures supply synthetic future
compatible and malformed responses. These checks extend existing gates; they
are not a new product, compatibility framework or user-facing test mode.

Before completing the series, write a concise durable architecture document
and link it from README and CONTRIBUTING. Cover core/frontend ownership,
public-command composition, lifecycle decisions, resource retention and cleanup,
digest versus build inputs, SSH generations, the caller-serialization
obligation and its limits, security boundaries, and test/release
responsibilities. Keep public commands
and byte-format contracts in user documentation and link to relevant tests.
Verify the guide against the completed code; archived plans must not be needed
to understand or maintain the shipped contracts. This plan owns the final
cross-series documentation review and resolution of inconsistencies.

### Acceptance criteria

- Bare `jailbox` follows the eight-step sequence and reaches core only
  through public CLI child processes; the boundary check rejects in-process
  use of core internals.
- The identical composed environment is used for `up` and `connection-info`,
  and unchanged inputs produce an unchanged digest.
- 03.2.02's effective-policy composition contract is integrated and tested:
  hashed hosts match the rendered proxy filter, and in-project config anchors
  participate in both the digest and read-only protection. Editor attachment
  uses `connection-info`'s digest gate and never proceeds after its refusal.
- Machine commands no longer read any config file; the frontend owns the
  file, `init`, and `--config`, and `--no-editor` preserves the headless
  file workflow.
- This plan completes 03.2.06's init-guard handoff: tests prove initialization
  requires successful `status` output of exactly `absent` plus newline and uses
  no in-process container inspection. Other states, malformed output, and
  command failure refuse before writing configuration.
- `ssh-config` is removed and `connection-info` is the frontend's only
  connection-data source; editor `http.proxy` follows `proxy_url` exactly.
- Equivalent effective allowlists permit healthy sandbox reuse regardless of
  member order or repetition, and generated editor JSON preserves accepted
  connection values exactly.
- No editor launches after any child-command failure.
- Consumer fixtures prove compatible extensions work and malformed or failed
  responses refuse; all four owning gates pass.
- Durable architecture and public contracts match the completed implementation
  and link to the tests that verify them.
- Documentation review verifies the caller-serialization requirement and the
  frontend's lack of locking, including the `up` / `connection-info` interval
  and interference from independent callers, as assigned by the charter.
- Editor validation refuses before any machine command runs and names every
  unmet requirement in one refusal; core `doctor` reports no editor state.
- Image/editor compatibility remains documented, with the automatic
  Alpine/VS Code launch and doctor warnings and their coupling removed.

### Non-goals

- A repository split, second installed executable, Go implementation, TOML
  format, or `WRAPPER_SETUP` mechanism (all deferred with the split).
- Automatic recovery, direct state inspection, Git-integrity monitoring,
  credential management, scheduling, or editor support outside the tested
  matrix.

## Implementation detail

A dedicated `host/frontend.sh` is one suitable organization; choose whichever
keeps the public CLI calls easy to audit, and expose no private core lifecycle
helpers to it. The test-fixture mechanisms named above are guidance: reuse the
existing test harnesses and 03.2.07's shared lifecycle matrix rather than
adding parallel frameworks.

Use a consistent representation of the effective host set for proxy rendering
and reuse comparison. Keep JSON string encoding and connection-record parsing
in focused, format-specific helpers; shell quoting is not JSON encoding. Pass
local process arguments as arrays and reuse the same settings interpretation
for generation verification and later inspection. These mechanisms support the
contracts above without introducing a general serialization framework.
