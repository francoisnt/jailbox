# 3.2.14. Remove extracted jailbox surfaces

## Goal

Remove every configuration-file and editor-facing surface from jailbox after
the independent JailIDE replacements pass, leaving a coherent environment-only
core in the same commit.

## Sequence

Implement in jailbox only after 03.2.11–03.2.13 pass portable/editor against
the exact coordinated 03.2.01–03.2.09 core artifact. Keep `jailide/` nested
and locally excluded. After this change, rerun both products before 03.2.15.

## Configuration-file removal

Delete the temporary adapter owned by 03.1. In `host/common.sh`,
`host/validation.sh`, `host/preflight.sh`, and the `jailbox` entrypoint,
remove file selection/parsing, default/selected anchor state, line diagnostics,
`init` publication, and `--config` parsing. Remove corresponding declarations
and help from `host/public-api.sh`.

Remove symbols and all callers including:

- `DEFAULT_CONFIG_PRESENT`, `DEFAULT_CONFIG_INPUT`, and
  `SELECTED_CONFIG_INPUT`;
- config-path/selected-config parser state and the temporary conversion into
  environment-shaped values;
- `init` dispatch/template/public API and configuration-file preflight; and
- `--config` ordering/selection guards and tests.

In `finalize_effective_readonly_paths` in `host/container-runtime.sh`, remove
only default/selected config-file additions. Preserve
`SELECTED_DEV_CONTAINERFILE_INPUT`, automatic Containerfile protection, and
its immediate pre-mount recheck.

Environment callers using `JAILBOX_CONFIG_*` do not change. There is no
stable dual-interface release and no automatic migration; pre-user fixtures
are recreated as JailIDE configuration.

## Editor and `ssh-config` removal

Delete `host/editor.sh` and every editor-owned state path, `EDITOR_BIN`
preflight, `EDITOR`, `JAILBOX_EDITOR`, `JAILBOX_CONFIG_EDITOR`, editor
binary/extension discovery, profile/settings generation, bootstrap-host
composition, editor-specific image warnings, and bare-launch editor dispatch.
Bare jailbox remains the 03.1 usage error and `up` the explicit launch.

Delete `ssh-config`: remove its `CLI_FLAGS_WITHOUT_VALUES` and `CLI_HELP`
entries, dispatch in `jailbox`, and `print_ssh_config_instructions` from
`host/ssh.sh`. Machine clients use `connection-info`; human editor
instructions live in JailIDE.

Inspect `host/common.sh`, `preflight.sh`, `dev-image.sh`, `network.sh`,
`downloader-proxy.sh`, `container-runtime.sh`, `ssh.sh`, the entrypoint,
and public declarations for leftover editor/config branches. Retain downloader
proxy runtime behavior and remote-session proxy variables; remove only
editor-bootstrap/profile ownership.

## Container/runtime boundary

Do not remove remote IDE-server compatibility packages from
`container/setup.sh` or wrapper image construction. Rewrite editor-specific
comments as generic SSH-attached development-runtime compatibility. Update SSH
mount rationale in `host/container-runtime.sh`, `container/entrypoint.sh`,
and `container/setup.sh`: host-generated server authentication is read-only,
`--userns=keep-id` supplies StrictModes ownership, and mutable daemon state is
in `/run`.

Keep jailbox tests for wrapper images, SSH generation/readiness/pinning, proxy
session variables, mounts, lifecycle, identity, digest compatibility,
configuration validation, and container isolation.

## Test and workflow migration

Remove or transfer editor/config-file-only suites:

- `tests/unit/config-parser.sh`, `init-config.sh`,
  `editor-settings.sh`, and obsolete `ssh-config.sh` assertions;
- editor-only portions of preflight/network/downloader tests;
- `tests/e2e/editor-smoke.sh` and `editor-validate.sh`; and
- editor pins/jobs/matrix entries no longer consumed by jailbox.

Do not delete a whole mixed suite until its lowest-layer core assertions are
relocated to the nearest unit/runtime suite. Update `tests/run`,
`scripts/lint.sh`, `scripts/gen-tested-matrix.sh`, `versions.env`,
`.github/workflows/test-gates.yml`, PR/release/canary callers, and CI setup so
jailbox exposes exactly:

```text
tests/run portable
tests/run runtime
```

Portable remains discovery-based. Runtime exclusively owns wrapper/container
security and negative image cases. No editor binary/display is a jailbox gate
prerequisite.

Preserve the 03.2.10 toolkit manifest, candidate lock, deterministic generated
installer/package/release files, and their integration tests. Regenerate after
the final file-inventory change and prove the candidate toolkit still produces
the committed bytes; removal of editor/configuration surfaces must not fork or
inline the generic tooling implementation again.

Also preserve the `vendor/jailutils` gitlink, canonical `.gitmodules` URL,
allowlisted package-copy step, common commit/file-digest build metadata,
and jailbox integration tests. After the final file-inventory change, rebuild
the jailbox archive and wrapper image from the initialized pinned submodule;
prove both contain exactly their declared common files and metadata and that no
copied common source became tracked in jailbox. Core removal must not fork,
inline, or silently advance `jailutils`.

## Public API and documentation

Update `host/public-api.sh`, `scripts/public-api-diff.sh` fixtures, help,
usage, README, release notes, and install lifecycle tests for the final command
and configuration surface. Generated API comparison must classify every
removed interface under 03.2.01's bump policy.

Rewrite README around the environment-only substrate, explicit commands,
orchestrator examples, machine schemas, compatible attachment, and security
model. Link to JailIDE for human config/editor use. Document that stop removes
both containers and networks, applies recorded home mode, default ephemeral
mode removes home data, persistent/legacy mode preserves it, and clean always
destroys home/runtime state.

In the same commit update `AGENTS.md` and `CONTRIBUTING.md`: remove editor
gate and `host/editor.sh` ownership, keep strict environment data and the two
core gates, and align handoff instructions. This prevents repository guidance
from describing a tree that no longer exists.

## Security invariants

Preserve read-only roots, dropped capabilities, no-new-privileges, no engine
socket, project-external state, Containerfile protection, proxy-only egress,
strict pinned SSH, and fresh-per-generation credentials. Removing anchors from
core does not authorize callers to omit protection of their own inputs.

## Validation

Run jailbox `tests/run portable` and `tests/run runtime`. Install a package
from this exact candidate and run JailIDE `tests/run portable` and
`tests/run editor`. Search source, tests, workflows, and docs for
`jailbox.conf`, `--config`, `init`, editor variables/code, profiles,
bootstrap composition, `ssh-config`, and editor gate; every surviving mention
must describe removal/migration or JailIDE.

## Acceptance criteria

- Core contains no config parser/adapter/anchor/init/flag or editor/profile/
  extension/bootstrap/`ssh-config` implementation or public declaration.
- Containerfile protection, SSH-attached runtime packages, proxy session
  behavior, and every lowest-layer security assertion remain.
- jailbox has exactly portable/runtime gates and all repository guidance,
  workflows, generated files, version pins, and packaging agree.
- Environment callers and JailIDE pass against the exact final candidate with
  no source-checkout dependency.
- The complete superseded-surface sweep has no unexplained occurrence.

## Non-goals

- Removing SSH, downloader proxy, remote runtime compatibility, or generic
  attachment.
- Publishing either product, moving the nested clone, or changing settled
  lifecycle/security behavior.
