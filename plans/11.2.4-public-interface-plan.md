# 11.2.4. Public interface declared in Go

## Intent

Fourth member of `11.2-go-core-plan.md`. Once no Bash runtime code reads the
declarations, replace `src/public-api.sh` with a Go package as the single
source of truth for the public interface, and drive release versioning from it.

### Source of truth

- One Go package declares the public interface. It imports only the standard
  library, so a small program built from that package alone can print the
  surface of any source tree that contains it, including past release tags.
- The frontend and core import the package directly; nothing generates Go
  declarations from another format. Documentation generation, release version
  selection, and shell tests consume the printed surface.
- Per-member mappings still cover every declaration exactly, and a missing
  mapping fails explicitly.

### Declared surface

- Configuration keys, with type (scalar or list), namespace (machine or
  frontend-only), and default.
- CLI commands and flags, with value names, help text, the program that
  accepts each (`jailbox` or `jailcore`), and lifecycle membership.
- The field layout of the machine outputs `connection-info`, `status`, and
  `config-schema`.

The printed surface is a JSON document with a schema version. The release tool
reads every schema version the latest release tag may carry and rejects
unknown ones.

### Versioning

The release tool compares the surface at the latest release tag with the
current tree:

- Breaking: removing or renaming a key, command, or flag; changing a key's type
  or namespace; moving a command to the other program; removing, reordering,
  or changing a declared output field.
- Additive: a new key, command, or flag, or a new output field where the
  output's contract lets existing readers ignore it, such as trailing
  `connection-info` fields.
- Other changes, including help text and defaults, count as neither.

Bump rules stay as today: before 1.0, breaking suggests minor and additive
suggests patch; from 1.0, breaking suggests major and additive suggests minor;
otherwise patch. A requested minimum bump can only raise the suggestion.

The first release after this lands compares against a tag that still declares
the interface in `src/public-api.sh`. Read that file once for its names;
categories it never declared, such as output fields, do not count as changes.

### Migration

Remove `src/public-api.sh`, `src/host/api-support.sh`,
`scripts/gen-public-api.sh`, `scripts/public-api-diff.sh`,
`scripts/lib/public-api-values.awk`, and the Go declaration generator added by
`11.1-go-frontend-plan.md`. Replace `tests/unit/public-api.sh` and
`tests/unit/public-api-diff.sh` with Go tests. Point `tests/lib/core.sh`,
`tests/lib/lifecycle-contracts.sh`, and other test readers at the printed
surface. Drop `public-api.sh` from the source check in `src/install.sh` and the
syntax check in `scripts/build-tarball.sh`, and update the comment in
`.github/workflows/release.yml`. Regenerate the command reference in
`docs/automation.md` from the package. Update `AGENTS.md`, `CONTRIBUTING.md`,
and `ARCHITECTURE.md` wherever they name `src/public-api.sh`, including where
Go maintenance programs live.

### Acceptance

Go tests cover each breaking and additive classification, the transition from
a Bash-declared tag, and printing the surface from a past tree. The release
tool's tests run against fixture repositories. The documentation check and the
lifecycle-contract derivation keep failing on stale or missing entries.

## Implementation detail

`src/internal/` suits the declaration package. The release tool can extract a
tag's source tree with `git archive` and build the printing program there with
the current toolchain.
