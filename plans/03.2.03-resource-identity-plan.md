# 3.2.03. Deterministic resource identity

## Goal

Use exact deterministic names as project identity and remove the redundant
`jailbox.project` ownership-label model.

## Sequence

Implement after 03.2.02, whose digest replaces the reuse gate, and before
lifecycle convergence.

## Behavior

Through `host/project-id.sh`, derive the first 12 lowercase SHA-256 characters
of the canonical physical path and existing sanitized slug. All commands and
equivalent relative, absolute, and symlinked path spellings produce identical
container, network, volume, image, SSH alias, port, and runtime-state names. Require
`sha256sum` or `shasum -a 256`; remove the cksum fallback and unreachable
decimal port branch.

Make those removals specifically in `jailbox_project_hash_for_path` and
`jailbox_project_hash_port_offset`, including the obsolete decimal comment.

Remove `jailbox_resource_owner`, `jailbox_resource_ownership`,
`resolve_owned_resources`, and ownership-label creation/inspection. Exact-name
existence, structure, and digest determine handling. Names/labels are not
authentication against processes with the host user's Podman authority; retain
no engine socket and document this threat boundary.

## Test cleanup and migration

Replace `prune_stale_jailbox_resources`, which enumerates
`label=jailbox.project`, with a ledger outside each
`/tmp/jailbox-editor-*` and `/tmp/jailbox-e2e-*` fixture, recorded before
launch creates anything.
This preserves recovery after a crashed run's fixture directory vanishes.
Prune only exact recorded containers, networks, volumes, and images; never
sweep the shared prefix or unrecorded developer resources, including a sandbox
running the test. Names do not migrate; unlabeled compatibility follows 03.2.02.

Update `host/project-id.sh`, `host/container-runtime.sh`, `host/network.sh`,
lifecycle/runtime tests, both products' cleanup harnesses, and README.

## Acceptance criteria

- SHA-256 physical identity is consistent everywhere and no ownership label/API
  remains.
- Exact-name destructive behavior and host-authority limits are documented.
- Interrupted test cleanup can remove only harness-recorded objects.
- Existing SHA-256-derived names require no migration.

## Non-goals

- Host-user authentication, resource renaming, or prefix-wide pruning.
