# 3.2.04. Home-volume lifecycle, stop, and clean

## Intent

### Goal and sequence

Make data retention depend on creation-time metadata, independently of digest
compatibility. Persistence is the default to preserve existing data across
upgrades; ephemeral homes are opt-in.

Implement after `03.2.02-configuration-digest-plan.md` and
`03.2.03-resource-identity-plan.md`, before constrained up. Preserve the
explicit, configuration-independent cleanup boundary established by
`02-explicit-stop-plan.md` while changing which resources stop removes.

### Configuration and metadata contract

Add scalar `EPHEMERAL_HOME`, exposed to machine callers as
`JAILBOX_CONFIG_EPHEMERAL_HOME`. The only accepted effective values are the
exact lowercase tokens `true` and `false`. Omission defaults to `false`;
explicit empty values, whitespace-bearing values, alternate case, and all
other tokens fail configuration validation with exit status 1 and a diagnostic
on stderr before lifecycle mutation. Append the key after `PIDS_LIMIT` in the
scalar declaration order; 03.2.08 owns byte-exact schema verification of this
order. The effective value participates in the configuration digest.

Label new homes with `jailbox.ephemeral-home=true|false`. An absent label on a
legacy home means false and is never added or rewritten. Any present value
other than exact `true` or `false`, including an empty value, is corrupt.
Distinguish absent metadata, corrupt metadata, and inspection failure. Failed
inspection is an operational error, never evidence that a home is legacy or
safe to delete. Read home metadata before removing or reusing any resource,
as resource presence is already probed before removal: when a required home
inspection fails, up and stop abort with nothing mutated rather than
proceeding to a partial cleanup. Clean does not require home-policy metadata.
Core never labels a volume it did not create.

Persistent homes survive generations, policies, and versions. Ephemeral homes
survive only their development-container generation. Reuse preserves user
contents; only jailbox-managed proxy blocks may be replaced. 03.2.06 owns proxy
synchronization and its verification against the live network settings.

### Up and recovery

Persistent and legacy-false homes remain eligible for exact-name reuse under
requested false. Requested true against either is a persistent-to-ephemeral
change and refuses without mutating existing state, with warned `--clean`
then `up` guidance. Ephemeral-to-persistent uses explicit `stop` then `up`.

An orphaned true home whose development-container object no longer exists is
never reusable, even if every remaining digest matches. It blocks up until
explicit stop removes it, under either requested mode.

A corrupt-label home blocks up under either requested mode, whether or not a
development container survives. Refuse without mutating existing state and
recommend warned `--clean` then `up`; stop preserves that home and cannot
resolve this refusal. Never infer its mode from requested configuration.

Mode changes also invalidate the digest. 03.2.06 owns combined-refusal
precedence and convergence verification: recovery must resolve all applicable
refusals, including corrupt metadata, instead of sending the caller through a
stop that leaves the blocking home. Neither recovery runs automatically.

### Stop and clean

Stop determines the home's retention from its stored metadata before removing
anything. It then removes both project containers and all three project
networks, and removes the home last, only when that metadata is valid true.
A failed home inspection aborts stop with nothing removed. It preserves false,
legacy, and corrupt-label homes, warning for corrupt metadata. It performs this
cleanup even when neither container exists, so orphan recovery and interrupted
stop remain repeatable. Images survive stop. Network incompatibility alone
therefore requires stop then up, without deleting a persistent home.

Clean warns and removes this project's runtime state, the home at the exact
derived name whatever its label, and the three exact derived image names for
the project dev image, wrapper image, and proxy image, regardless of provenance.
An externally supplied dev image is untouched unless its name is deliberately
one of those three derived names. Cleanup targets must not change with loaded
image configuration.

Both commands use exact derived names regardless of digest, legacy status,
structure, or ownership labels; stop's home retention rule still applies.
03.2.03 owns documentation of this destructive name-as-identity collision
boundary. Stop and clean remain configuration-independent and require no
editor or SSH connection. Every clean recommendation warns that the project's
home and runtime state are permanently deleted.

### Acceptance criteria and verification ownership

- New homes record the effective mode, including default false; legacy homes
  remain unlabeled and read false. Invalid configuration refuses before mutation.
- Missing labels, present empty/invalid labels, and inspection errors produce
  their distinct required outcomes; corrupt homes refuse up under both modes,
  and a failed home inspection leaves stop entirely non-mutating.
- Stop applies stored policy even without containers, removes all project
  networks, preserves images, and recovers orphaned ephemeral homes.
- Clean removes the exact derived home and images without expanding its scope
  to other projects or a differently named external dev image.
- Directional recovery is non-mutating until explicitly executed, and every
  clean recommendation includes the permanent-data-loss warning.
- After successful stop, the container/network/home inventory is empty exactly
  when no home was preserved; successful clean leaves that inventory empty.
  03.2.08 owns subsequent status integration and unit/runtime verification:
  preserved false, legacy, or corrupt homes yield `stopped`, removed ephemeral
  homes yield `absent`, and clean yields `absent`. Images and host state do not
  affect those results. Status is not required to exist when this plan lands.
- 03.2.06 owns convergence integration and combined-refusal recovery tests;
  03.2.07 extends coverage with independently constructed interrupted and
  damaged states. These integrations remain required before the series releases.

### Non-goals

- Digest-gating homes, guessing malformed metadata, automatic recovery, or
  changing user content outside jailbox-managed proxy blocks.

## Implementation detail

### Existing implementation migrations

- Extend `ensure_home_volume` and `stop_jailbox` in
  `host/container-runtime.sh` for creation-time metadata and stored retention.
  Replace stop's container-only early return so absent containers cannot bypass
  network or orphan-home cleanup. Extend `clean_jailbox` for derived-image
  removal and warnings.
- The existing `jailbox_resource_label` in `host/container-runtime.sh` collapses
  absent labels and inspection failures into an empty result. Do not use that
  result to classify home policy; home inspection must preserve the distinctions
  required above without weakening the existing digest gate.
- Add the scalar declaration and false default to `CONFIG_SCALAR_KEYS` and
  `CONFIG_DEFAULTS` in `host/public-api.sh`, preserving the required placement.
  Revise the existing stop and clean entries in `CLI_HELP` to describe their
  retention and deletion behavior. Review the generated public API diff from
  `scripts/public-api-diff.sh` and the applicable release-version suggestion;
  this plan does not authorize a release.
- This plan owns replacing the `stale_networks` recovery branch in
  `require_compatible_project_resources` in `host/config-digest.sh`: network
  mismatches become recoverable through stop then up. 03.2.06 subsequently
  integrates home-aware recovery precedence.
- Replace the network-survival premise in `configure_network`'s comment in
  `host/network.sh`, retaining the requirement for a digest before creation.
  Rewrite README's claim that networks survive stop and require clean, and
  update its lifecycle/help guidance and threat model for stored home retention
  and exact derived-image deletion.
- Replace the existing assertion in `tests/unit/lifecycle.sh` that stop
  "preserves the home volume and project network" with assertions that stop
  preserves the unlabeled legacy home and removes the project network.
- Do not base clean's image targets on the launch-time value of
  `PROJECT_DEV_IMAGE`: `host/dev-image.sh` reassigns it to an external
  `DEV_IMAGE`. Derive cleanup targets from project identity.

### Tests and documentation

Update public API/help, configuration, lifecycle, digest-recovery, and runtime
coverage. Exercise valid, legacy, corrupt (including present empty), unreadable,
orphaned, and mode-change homes; interrupted/repeated stop; preserved contents;
exact image deletion; and warnings. Verify network-only mismatch recovery keeps
a persistent home and that no-container stop still removes networks and a true
home. Retain proxy-content preservation assertions; live-URL synchronization
integration belongs to 03.2.06.

Run `tests/run portable` and `tests/run runtime`. Deferred status checks land
with 03.2.08 using 03.2.07's shared matrix.
