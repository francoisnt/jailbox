# 3.2.08. `config-schema` and `status`

## Goal

Add two stable, read-only machine interfaces: declaration discovery for callers
that compose core configuration, and a one-word project lifecycle inventory.

## Sequence

Implement after 03.2.01–03.2.07 and 03.2.07.1, and before 03.2.09 and 03.2.11.
The schema consumes the canonical declarations created by 03.1. Status consumes
deterministic identity from 03.2.03 and the inventory/lifecycle rules from
03.2.04–03.2.06.

## `config-schema` contract

`jailbox config-schema` reads `CONFIG_SCALAR_KEYS` and `CONFIG_ARRAY_KEYS`
from `host/public-api.sh` and emits exactly one record per key in public
declaration order: every `CONFIG_SCALAR_KEYS` member, then every
`CONFIG_ARRAY_KEYS` member. With 03.2.04's `EPHEMERAL_HOME` in place that is:

```text
DEV_IMAGE<TAB>scalar
DEV_CONTAINERFILE<TAB>scalar
DEV_BUILD_CONTEXT<TAB>scalar
DEV_TARGET_STAGE<TAB>scalar
MEMORY_LIMIT<TAB>scalar
CPU_LIMIT<TAB>scalar
PIDS_LIMIT<TAB>scalar
EPHEMERAL_HOME<TAB>scalar
EGRESS_ALLOW<TAB>array
READONLY_PATHS<TAB>array
```

A new key is appended to its declaration array rather than inserted, so this
order is stable and both this schema and 03.2.02's digest stream stay
predictable as keys are added.

Plans 7 and 8 automatically add `WRITABLE_PATHS` and `HIDDEN_PATHS`. The
final schema has no `EDITOR`. Names use the validated uppercase-key grammar;
types are only `scalar` and `array`. Output has no heading, defaults, values,
colors, or diagnostics. The jailbox release version governs the schema.

The command requires no project, configuration, Podman, SSH, hash utility, or
editor. Declare it as a non-lifecycle command in `host/public-api.sh`, with
the required help and handler mappings. Render it from the existing key
declarations. Verify that usage and public-API comparison include it
automatically, and cover its dependency requirements in command tests.

Consumers must reject malformed records, duplicate keys, invalid names,
unknown types, and the absence of a core key they specifically require.
Unknown additional valid keys are accepted within a compatible release range.

## `status` contract

`jailbox status` derives project identity from the canonical physical current
directory and, on success, exits zero and prints exactly one word plus newline:

```text
absent
running
stopped
```

Its exhaustive stable inventory is the derived development container, proxy
container, project networks, and home volume. It reports `running` whenever
the development container is running; `stopped` when it is not running but at
least one inventory resource exists; and `absent` only when none exists.
Partial or unhealthy state may produce diagnostics on stderr but does not add a
fourth stdout state.

Failed identity derivation or required Podman discovery exits nonzero, leaves
stdout empty, and reports the error on stderr. Failed existence probes and
failed or malformed development-container inspection must not become an
inventory classification, even when a failed producer emits plausible output.
Consumers must check both exit status and exact stdout before using the result.

Exclude project images because they are rebuildable and survive `stop`.
Exclude host SSH/runtime state because `doctor` owns it. Thus a valid
ephemeral home removed by `stop` can leave `absent`; a persistent, unlabeled
legacy, or malformed-label home leaves `stopped`; `--clean` leaves
`absent`. These results are the initialization gate for the frontend's
`init` (03.2.11).

Status requires Podman and project identity (including SHA-256 hashing) but no
configuration, SSH, configuration-digest computation, or editor. Declare it as a
non-lifecycle command with the required help and handler mappings. Its handler
owns a focused read-only inspection path; do not route it through launch
preflight or lifecycle mutation.

## Consumer contract verification

This plan owns producer tests for byte-exact schema output, including no
progress messages on stdout and no partial success output on validation failure.
03.2.11 owns consumer-side version-range and schema compatibility fixtures,
including valid additional keys and rejection of missing required keys.

## Security invariants

Neither command mutates resources or emits configuration values, secrets, SSH
material, container names, or paths beyond its declared schema. Deterministic
identity remains canonical.

## Tests and documentation

- Extend public-API, CLI parsing, help, and preflight unit suites for both
  commands.
- Add golden schema tests for declaration order, type mapping, automatic added
  keys, and declaration-integrity failures.
- Add status unit/runtime fixtures for empty, each single inventory resource,
  partial combinations, running development container with unhealthy support,
  stopped containers, each home-label class, and image-only state.
- Add status producer regressions for failed identity derivation, failed
  existence probes, and failed or malformed development-container inspection,
  including failed producers with empty or plausible output. Assert nonzero
  exit status, empty stdout, diagnostics on stderr, and non-mutation.
- Complete 03.2.07's deferred status integration by extending that plan's
  shared matrix rather than duplicating its state expectations: run `status`
  against every constructed adversarial state and its recovered state, assert
  successful exit and the exact inventory-derived word plus newline. Verify
  non-mutation through a bounded set of full before/after comparisons covering
  absent, running, stopped, damaged support resources and SSH, recovery, and
  stop/clean outcomes for every home-label class. Growing interruption coverage
  must not multiply these expensive comparisons. SSH damage and health failures
  must not change the inventory classification.
- Assert stdout byte-for-byte and keep diagnostics on stderr.
- Document the two schemas in README machine-interface guidance.

Run `tests/run portable`, `tests/run runtime`, and `tests/run matrix`.

## Acceptance criteria

- `config-schema` is the exact two-column declaration-derived contract and
  gains plans 7/8 keys without a local list.
- Successful `status` exits zero and emits exactly one of three words plus
  newline from the exhaustive inventory; images and host-side state never
  affect it. Failed required discovery exits nonzero with empty stdout and
  diagnostics on stderr, never a success classification.
- This plan owns 03.2.04's deferred status integration and unit/runtime
  verification through the shared 03.2.07 matrix: after successful stop,
  preserved false, legacy, and corrupt-label homes yield `stopped`; removed
  ephemeral homes yield `absent`; successful clean yields `absent`. Verify
  byte-exact stdout and non-mutation, excluding images and host state.
- This plan owns and completes status coverage of the entire 03.2.07 matrix,
  including recovery results and byte-exact stdout, with the bounded
  non-mutation coverage above in the matrix gate.
- Both commands are read-only, configuration-independent, secret-free, and
  covered by generated public-API comparison.
- The frontend and external orchestrators require successful `status` with
  stdout exactly `absent` plus newline before permitting initialization;
  command failure, malformed output, and other states refuse initialization.

## Non-goals

- Defaults or validation metadata in `config-schema`.
- A `degraded` status or a stable detailed-health schema.
- Current-policy compatibility, repair, or cleanup; 03.2.09 and lifecycle
  commands own those behaviors.
