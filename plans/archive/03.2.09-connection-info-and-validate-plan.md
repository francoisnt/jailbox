# 3.2.09. `connection-info`, shared attachment validator, and `validate`

## Intent

### Goal

Provide one complete read-only attachment validator, a stable machine schema
for SSH consumers, and a non-mutating configuration check. Each operational
command explains its own failures and actionable recovery; a separate health
check is not required to understand a refusal.

### Sequence

Implement after 03.2.02–03.2.08. 03.2.09.1 and 03.2.09.2 call the shared
validator rather than defining attach compatibility themselves; the editor
frontend (03.2.11) consumes it through `connection-info`.

Editor-filtered attachment depends on 03.2.11's policy composition migration.
Until that integration, bare launch adds editor bootstrap hosts through
`EDITOR_BIN` while machine attachment does not, so attachment refuses that
filter. 03.2.11 owns removing this process-dependent core policy, passing the
same composed `EGRESS_ALLOW` to launch and attachment, and verifying filtered
editor launch followed by successful `connection-info`. This intermediate
limitation must be resolved before the series releases; do not weaken filter
comparison or add editor discovery to attachment to accommodate it.

### Shared attachment validator

Compose the existing read-only checks under one attachment entry point, keeping
lifecycle/runtime, SSH, network, and live-session rules with their current
owners. Reuse the batched resource/property checks and streamed session
validation rather than introducing parallel implementations. It accepts the
final validated environment policy and establishes, before attachment:

- exact derived resource names and the exhaustive required resource set;
- a running, SSH-responsive development container;
- matching current `jailbox.config-digest` labels on every required
  resource and every other existing member of 03.2.02's digest inventory
  (both containers and plain, internal, and external project networks),
  including networks outside the requested mode;
- internally consistent container/network/home attachments and valid home-mode
  metadata;
- complete host and mounted SSH-generation material, ownership, modes, file
  types, pinned identity, and generated client configuration; and
- when filtering is enabled, the required running proxy and live network URL.

It creates, starts, stops, repairs, replaces, labels, or removes nothing.
Failures distinguish absence, stopped/unresponsive state, legacy or
inconsistent digest, structural damage, SSH damage, and proxy failure, and give
recovery appropriate to the observed state and requested policy. Exact names,
not `jailbox.project`, identify resources.

An otherwise compatible absent or stopped sandbox, or one needing only managed
downloader synchronization, requires `up`, not a preceding `stop`. Incompatible
digest, structure, or SSH state requires `stop` then `up` when the home remains
eligible. Preserve 03.2.06's home-aware precedence: corrupt retention metadata
and persistent-to-ephemeral changes require warned `--clean` then `up` even
when other incompatibilities coexist; ephemeral-to-persistent changes and
orphaned ephemeral homes require `stop` then `up`. Stop guidance explains
recorded home retention or deletion. Failed home inspection is an operational
error, never evidence for destructive recovery. Unsafe host paths or unrelated
network occupants require their specific manual correction rather than a
recovery sequence that cannot resolve them. Nothing runs recovery automatically.

Reuse 03.2.06's applicable required read-only health checks: runtime hardening,
protected mounts, socket isolation, and proxy readiness/enforcement gate
attachment. Required checks that fail or cannot be established refuse; upstream
website availability remains advisory, and failed transport is not evidence of
policy denial. Validate live session and managed downloader settings without
synchronizing or repairing them.

Configuration, digest, and host-observable structural checks precede live SSH
validation. Live checks may use SSH; all required checks finish before emitting
connection records or executing a caller's command or interactive shell.
The streamed session checks alone do not establish digest compatibility,
SSH-generation integrity, proxy readiness/enforcement, or managed downloader
configuration; retain those checks in the complete validator.

Keep one implementation of each shared health or compatibility rule, with
command-specific setup and diagnosis around it. Status remains an inventory
query, while `validate` checks configuration and local inputs without inspecting
a sandbox. Neither inherits attachment's complete preflight; running inventory
and valid configuration do not establish sandbox health. Do not reuse observations across lifecycle mutation
or remove required live checks merely to reduce inspection calls.
Preserve batching within each invocation without sharing successful validation
between CLI processes. The streamed validation payload remains a host-shipped
input, excluded from wrapper image inputs; installed container helpers remain
image inputs.

### `connection-info` schema

`jailbox connection-info` loads and validates the complete environment
configuration, computes the current digest, invokes the shared validator, and
on success emits these fixed-order NUL-terminated records:

```text
ssh_config<TAB>ABSOLUTE_PATH<NUL>
ssh_host<TAB>HOST_ALIAS<NUL>
remote_path<TAB>ABSOLUTE_PATH<NUL>
project_id<TAB>PROJECT_ID<NUL>
proxy_url<TAB>PROXY_URL_OR_EMPTY<NUL>
```

Attachment-time digest computation uses 03.2.02's read-only Containerfile
classification before the validator compares labels. A missing explicit or
implicit selection emits the digest's `containerfile<TAB>missing` record and
leads to stale-sandbox guidance; it must not trigger an image build or the
launch-only missing-input error. `DEV_IMAGE` emits `none` without inspecting
Containerfile candidates. The exec and shell consumers use the same
attachment-time digest behavior. The validator computes the attachment-time
digest and never builds images.

Values are emitted verbatim. Readers split each NUL-delimited record on its
first TAB. Field names match ASCII `[a-z][a-z0-9_]*`, so the split is
unambiguous; the framing can preserve any value byte except NUL. Reject a
record without a separator, an invalid field name, duplicate records, a missing
required field, or a stream whose final record lacks its NUL terminator. The
five required records appear exactly once in the stated order. Future unknown
valid records may follow them and consumers ignore those records after checking
their framing and uniqueness. Consumers validate all required values as paths,
aliases, project IDs, or proxy URLs according to their owning policy.

The required values have these meanings:

- `ssh_config`: the absolute path to the validated generated client config.
- `ssh_host`: the exact generated SSH host alias, using 03.2.03's deterministic
  resource-prefix spelling; it currently also names the development container.
- `remote_path`: the absolute project working directory inside the sandbox,
  currently `/home/jailbox/project`, not the host project directory.
- `project_id`: 03.2.03's first 12 lowercase hexadecimal SHA-256 characters of
  the canonical physical host project path, matching `[0-9a-f]{12}`; not the
  resource prefix or the full configuration digest.
- `proxy_url`: empty without filtering, otherwise the validated live internal
  proxy endpoint `http://<IPv4-address>:8888`, without credentials, path,
  query, or fragment.

Byte-preserving framing does not widen the accepted configuration or SSH path
syntax. Reject values forbidden by their owning policy before publication;
preserve every accepted byte without trimming or escaping it. Consumer tests
distinguish framing support for TAB/newline bytes from semantic acceptance of
required fields. Unknown trailing values are opaque after framing checks.

The output is a byte stream, not line-oriented text. A shell consumer reads one
record at a time with `IFS= read -r -d ''` or first writes stdout to a file; it
never captures the complete stream in a shell variable because shell variables
cannot preserve NUL bytes.

`proxy_url` is required: live collision-fallback-aware internal URL when
filtering, empty otherwise. Do not expose allowlists, private-key paths,
known-host contents, additional engine inventory, or raw configuration. The
required public SSH alias is permitted even though it equals a container name.
jailbox alone provides remote `NO_PROXY` and `no_proxy` in generated SSH
configuration.
The jailbox release version governs this schema.

Proxy URLs must not fall back to container names: the internal network has DNS
disabled. When filtering is enabled and no live or derivable subnet yields a
proxy address, fail with a diagnostic instead of emitting an unusable URL.

Declare the command as non-lifecycle in `host/public-api.sh`, with the required
help and handler mappings; usage and public-API comparison derive membership
from that declaration. Its handler owns configuration and attach validation.
It needs Podman, SSH, ssh-keygen, SHA-256, and project identity, but no Base64,
editor, config file, or `cksum`.

### `validate`

`jailbox validate` checks canonical environment configuration and the local
inputs required for a new launch, using the same rules as `up`. It applies
normal defaults, rejects unknown or malformed environment declarations, checks
value and array semantics, and validates configured paths, containment,
symlinks, file types, and automatically protected launch inputs. When building
from a Containerfile, require the launch-time selection and a valid build
context; missing inputs fail with launch guidance rather than attachment-time
stale-sandbox guidance. `DEV_IMAGE` retains launch's precedence and bypasses
unused Containerfile/build-context discovery. Do not invent image-reference or
Containerfile-language validation that launch itself does not perform locally.

Use one implementation of configuration and local-input rules across validate
and launch. Validation evaluates inputs as they exist now; launch rechecks them
at its required boundaries. It does not inspect resources or images, compute
compatibility against an existing sandbox, contact registries, build, pull,
probe an image, allocate ports, open SSH, create runtime directories, or write
project/home state. It requires only the local tools needed by these checks,
not Podman, SSH, ssh-keygen, image-build cksum, an editor, or resource-identity
hashing. Engine availability, image contents, Containerfile build success,
port availability, runtime compatibility, and sandbox health remain unchecked.

Exit zero with a short human-readable success message explicitly limited to
configuration and local inputs. Exit nonzero on invalid configuration or a
failed required read; send actionable diagnostics to stderr and no success
message to stdout. Output text is not a machine schema; callers use exit status.
Identify the offending key or path without dumping the configuration. Every
operational command retains its own validation and recovery diagnostics; never
require users to run validate to discover why another command failed.

The machine command consumes only environment configuration, even when no
`JAILBOX_CONFIG_*` variable is set; it does not fall back to `jailbox.conf`.
03.2.11 owns the file-facing form `jailbox --config PATH validate`, including
`--config jailbox.conf validate` for the default file. That frontend parses and
composes the file using its existing parser and headless launch composition,
then invokes the environment-only child `jailbox validate`. It checks file-only
key syntax but does not discover an editor or add editor bootstrap hosts;
success certifies the file's headless machine policy and local inputs, not
editor readiness. Before 03.2.11 implements this form, reject `--config` with
validate explicitly. 03.2.11's integration tests must prove that inherited
machine environment cannot alter the composed file policy.

### Command migration and connection instructions

Declare `validate` as non-lifecycle and remove the existing `doctor` command
from the public CLI, help, handlers, tests, and documentation. Do not retain a doctor alias with
changed semantics. Classify both declaration changes under the release bump
policy; the removal is part of this unreleased series. Consolidated sandbox
health diagnosis is backlog work, not an acceptance requirement of this plan.
This replaces the deferred doctor-diagnosis handoffs from archived 03.2.07 and
03.2.08; attachment, inventory, recovery, and operational-failure diagnostics
remain required. `validate` and `ssh-config` take no trailing arguments;
03.2.11 owns the explicit frontend file-selection exception for validate.

Retain `ssh-config` as a core-owned, configuration-independent human command
for connection instructions. Derive the generated client-config path and host
alias from project identity, show whether the config exists, and print a safely
quoted `Include` instruction. Support absent and stopped sandboxes without
Podman or SSH. Do not read or execute existing SSH configuration or manufacture
a ready-to-use host block from default or guessed policy; path existence does
not certify safe attachment. If a path cannot be represented safely in Include
syntax, explain that limitation instead of emitting an incorrect instruction.
Editor setting names belong in documentation, not this core output. Machine
consumers and the frontend obtain validated connection data only through
`connection-info`, never by parsing ssh-config's human output.

### Consumer contract verification

Validate the complete result before emitting success records. Producer failures
must emit no partial connection record stream; diagnostics stay on stderr.
03.2.11 owns end-to-end consumer tests for valid trailing fields, malformed
streams, incompatible release ranges and failures accompanied by plausible
stdout. Consumers require both exit success and a complete valid record stream.
Those fixtures enforce the field-name grammar and required value meanings above,
including the project hash versus resource prefix distinction and opaque valid
trailing values.
Transport interruption can truncate output, so consumer framing validation
remains mandatory even when producer validation succeeds.

### Security invariants

All checks precede attachment and preserve read-only roots, dropped
capabilities, no-new-privileges, socket isolation, proxy-only egress, and strict
host-key state. Machine output contains connection metadata but no secret.

### Acceptance criteria

- All attachment consumers invoke one validator covering every policy-bearing
  resource and SSH/network dependency.
- Relevant attachment and lifecycle refusals identify the observed problem and
  the working recovery action, including home-deletion warnings when needed.
  Reuse focused fixtures for recreated networks, partial SSH generations, stale
  managed settings, and corrupt home metadata; check diagnostic facts rather
  than full wording and execute the stated recovery under the intended policy.
  Inspection errors must not imply corruption or destructive recovery, and
  states requiring manual correction must name that prerequisite. Exec and
  shell own their command-level assertions under 03.2.09.1 and 03.2.09.2.
- This plan owns 03.2.06's read-only health integration: extend 03.2.07's shared
  matrix with required hardening, mount, socket, proxy, and SSH failures versus
  advisory upstream outages. Required failures prevent connection records and
  attachment without mutation, builds, or managed-home writes. Validate
  failed-resume leftovers by observed health rather than treating a running
  inventory state as proof of successful convergence.
- This plan owns integration and verification of 03.2.02's complete-inventory
  digest gate in attachment validation, including stale networks outside the
  requested mode. Missing-Containerfile digest classification produces
  stale-sandbox refusal before transport without building or mutation;
  `DEV_IMAGE` bypasses that discovery. Exec and shell own their command-level
  integration tests in 03.2.09.1 and 03.2.09.2.
- Connection-info emits the exact required schema only after validation, with a
  live proxy URL or required empty value and no secret.
- Required records preserve every accepted value byte, use the specified field
  grammar and value meanings, and reject malformed NUL framing.
- Validate and launch share configuration/local-input rules. Validate succeeds
  without engine or transport access, never mutates state, and does not claim
  sandbox health or build success. Invalid input and failed required reads fail
  without success output.
- The public doctor command is removed, while ssh-config retains safe human
  connection instructions independently of configuration and sandbox existence.
- 03.2.11 owns file parsing/composition and end-to-end verification of the
  explicit file-validation form; core validation remains environment-only.

### Non-goals

- Lifecycle mutation, duplicate configuration or attachment rules, exposing the
  allowlist, aggregate sandbox health diagnosis, or proving image/build/editor
  readiness through configuration validation.

## Implementation detail

The locations below identify existing code to migrate toward the binding
outcomes in Intent. They do not prescribe helper organization or a second
implementation of shared rules.

- Remove doctor from `CLI_OTHER_COMMANDS` and `CLI_HELP` in `host/public-api.sh`,
  `CLI_COMMAND_HANDLERS` in `host/common.sh`, `run_doctor` in `jailbox`, and
  `doctor_jailbox` in `host/container-runtime.sh`, including its unvalidated SSH
  probes and editor-specific branches. Add validate through those declaration
  and dispatch mechanisms. Update existing doctor CLI fixtures rather than
  preserving an obsolete diagnostic implementation.
- Refactor `run_ssh_config` and `print_ssh_config_instructions` to retain only
  identity-derived human instructions, removing configuration loading, launch
  initialization, proxy synthesis, editor settings, and rendered host blocks.
- Update README.md's configuration-consumer prose independently of its generated
  command reference: add connection-info and validate as configuration consumers,
  remove doctor, and move retained ssh-config to the configuration-independent
  list, removing its obsolete "for now" qualification. Describe validate as
  environment-only and leave the explicit file-validation documentation to
  03.2.11's frontend handoff. Regenerate the command reference through
  `scripts/gen-public-api.sh` rather than editing the generated table by hand.
- Rewrite README.md's Troubleshooting introduction, which currently starts with
  `jailbox doctor`, around the failing command's own explanation and recovery
  guidance. Present validate as an optional configuration/local-input check,
  status as inventory, and ssh-config as connection instructions, without
  implying any of them replaces attachment health checks or must be run to
  understand another command's failure.
- Separate build-context classification in `build_or_select_dev_image` from
  image construction so validate and up share the same required local checks.
  Reuse configuration loading and path validation without invoking launch setup.
- Remove `configure_proxy_env`'s name-based `http://$PROXY_NAME:8888` final
  fallback in `host/network.sh` to satisfy the usable-proxy-URL requirement.
- Remove the deferred doctor-diagnosis field and its plumbing from
  `lifecycle_matrix_rows`, `matrix_observe`, their callers, and unit fixtures.
  Retain attachment verdicts and recovery/retention assertions; keep any
  diagnostic checks that test actual lifecycle-command failures. Replace logged
  `health-dependent` placeholders in fault observers with independent attachment
  assertions, without constructing a separate diagnostic matrix.
