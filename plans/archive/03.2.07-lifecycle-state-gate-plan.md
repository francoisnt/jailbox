# 3.2.07. Constructed lifecycle-state runtime gate

## Intent

### Goal

Prove lifecycle contracts against interrupted and externally mutated states,
not only clean command transitions.

### Sequence

Implement after 03.2.06. It adds adversarial coverage without redefining the
contracts owned by 03.2.03–03.2.06.

The complete matrix also depends on later diagnostic interfaces: 03.2.08
owns integration and verification of `status` against every constructed state,
and 03.2.09 owns the corresponding `doctor` and attachment-validator coverage.
Those assertions land with their owning interfaces; this plan establishes the
fixtures and lifecycle assertions while keeping the existing gates passing.

### Constructed matrix

Directly construct interruption after each stop stage; either container missing;
missing/disconnected networks; stopped containers; orphaned ephemeral,
persistent, legacy, and corrupt-label homes; missing/altered/wrong-permission
SSH files; missing/inconsistent/mismatched digests; unexpected attachments;
partial up failure; SSH creation failure before/during container creation; and
collision-fallback network selection.

Network cases include one or more missing networks, removal/disconnection while
containers survive, and unexpected surviving attachments. Exercise unlabeled
homes under both requested modes. SSH cases include wrong types, ownership, and
modes. Inject failures after each stop stage and both before and during
development-container creation.

For every state assert whether up reconciles or refuses, refusal non-mutation,
invocation-only rollback, stop/clean outcomes, prescribed recovery, home
retention/removal, and live proxy propagation where applicable. Byte-exact
`status` and the required human diagnostic facts from `doctor` land with
03.2.08 and 03.2.09 respectively. Test ledgers must obey 03.2.03 and never
sweep developer resources.

### Shared acceptance matrix

Maintain one executable matrix of meaningful absent, partial, running, stopped
and damaged states. Each row records expected up, status, doctor,
connection-info, exec, shell, stop and clean outcomes, retained resources and
recovery. Interfaces that land later extend these same cases; do not create
independent competing expectations. Expected outcomes come from the owning
contracts, not from the implementation being tested.

Test each mutating command's initial-state outcome from an independently
reconstructed instance of the row, so an earlier up or cleanup cannot mask the
state under test. Read-only commands may share an instance when each verifies
non-mutation. Exec and shell probes must account for writes caused by successful
attachment or command execution before sharing an instance. Recovery sequences
deliberately continue from the observed failure or interruption state and verify
their resulting state separately.

Include combined failures, especially home-mode mismatch plus digest mismatch,
and failures between each persistent mutation step in up and stop/clean.
Choose additional representative combinations from the owning contracts to
exercise interacting refusals, recovery precedence, and dependency retention;
an exhaustive cross-product is not required.
Snapshot pre-existing resource identity, configuration, home contents and SSH
material; verify pre-mutation compatibility refusal preserves them. Failure
after an allowed start follows 03.2.06's distinct contract: surviving object
identities and SSH material remain, without restoring process state, tmpfs, or
startup home writes. Rollback removes only invocation-created artifacts safe
to remove; dependencies needed by survivors remain and are reported.
Execute the stated recovery under the intended policy and verify it
resolves all applicable refusals with the promised data retention. Forced
termination need not run rollback: assert the resulting partial state has the
documented explicit recovery.

03.2.08 owns status integration; 03.2.09 owns doctor and connection-info;
03.2.09.1 and 03.2.09.2 own their command-level matrix integrations.

Keep this editor-independent matrix in jailbox runtime. The editor gate
uses positive wrapper images and does not inherit negative core image cases.

### Acceptance criteria

- Every listed state is constructed directly or through controlled failure
  injection, rather than relying only on completed public transitions. Public
  commands may prepare a healthy baseline before independent damage or
  interruption constructs the state under test.
- Diagnosis and recovery are deterministic and all pre-mutation compatibility
  refusal snapshots remain unchanged.
- This plan owns 03.2.06's failed-resume integration: inject readiness failure
  after starting a surviving container and failure after creating a missing
  proxy dependency. Surviving containers are never automatically stopped or
  removed, generation identities remain unchanged, and needed dependencies
  remain. Diagnostics report observed final state, incomplete cleanup, and
  recovery. Execute recovery and verify stored home retention, distinguishing
  allowed startup/managed-block changes from unrelated content loss.
- Rollback and recovered home/proxy results match their owning contracts.
- Each recovery restores service and proves home retention/removal from recorded
  metadata.
- Combined-failure rows execute recovery and verify all refusals are resolved;
  interrupted up rows verify the applicable pre-mutation or post-start
  preservation contract. Interrupted stop/clean rows preserve completed
  removals and dependencies required by remaining containers, including SSH
  material; retry completes cleanup with the promised home retention/removal.
  Observed partial states must respect the documented removal order: both
  containers and project networks precede home removal. Stop removes the home
  only for stored valid true metadata; clean removes it regardless of metadata.
- Completion of the full matrix's diagnostic coverage is assigned to 03.2.08
  for byte-exact status and 03.2.09 for doctor and attachment validation; those
  integrations remain required before the series releases.

### Non-goals

- A fourth user-facing gate or redefining lifecycle behavior.

## Implementation detail

Reconcile existing constructed-home coverage in `assert_home_lifecycle` in
`tests/e2e/headless.sh` and lifecycle, convergence, and SSH damage coverage in
`tests/unit/lifecycle.sh`, `tests/unit/convergence.sh`, and
`tests/unit/ssh-generation.sh` with the shared cases. Reuse or migrate those
fixtures where useful, retaining focused unit assertions without maintaining
competing expectations. Mocked coverage does not replace the matrix's required
runtime evidence.

Order injected failures with controlled process barriers rather than timing
sleeps, so interruption points are deterministic.
Implement the constructed states in the runtime integration/system harness and
focused lifecycle fixtures under `tests/integration/` and `tests/unit/`;
extend `tests/e2e/headless.sh` only where full CLI recovery is required. Register
any new runtime suite in `tests/run` or invoke it from an existing runtime
suite; integration scripts are not automatically discovered. Run
`tests/run portable` and `tests/run runtime`.
