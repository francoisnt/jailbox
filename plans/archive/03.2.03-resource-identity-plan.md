# 3.2.03. Deterministic resource identity

## Intent

### Goal

Use exact deterministic names as project identity and remove the
`jailbox.project` ownership-label model.

### Sequence

Implement after 03.2.02, whose digest replaces the reuse gate, and before
lifecycle convergence.

### Behavior

Preserve the existing identity derived from the first 12 lowercase SHA-256
characters of the canonical physical path and the existing sanitized slug.
The CLI already canonicalizes the project directory with `pwd -P`; lock in
that invariant with regression coverage across equivalent relative, absolute,
and symlinked path spellings. Container, network, volume, image, SSH alias,
port, and runtime-state identities must remain consistent. Require
`sha256sum` or `shasum -a 256`; remove the cksum fallback and unreachable
decimal port branch.

If neither SHA-256 tool is available, fail with a missing-dependency error
naming both alternatives before any resource operation. Hashing failures must
propagate rather than produce partial or empty identities. This applies to
every command requiring project identity, including `stop` and `--clean`,
without making those commands load configuration. Identity initialization
precedes general preflight, so the dependency check must work at that point.

Make those removals specifically in `jailbox_project_hash_for_path` and
`jailbox_project_hash_port_offset`, including the obsolete decimal comment.
Preserve the separate cksum dependency for image-build cache busting in
`host/preflight.sh`.

Remove `jailbox_resource_owner`, `jailbox_resource_ownership`,
`resolve_owned_resources`, and ownership-label creation/inspection. Migrate
`require_sandbox_absent` in `host/container-runtime.sh` to give `jailbox stop`
guidance for either present container without ownership or digest checks,
until 03.2.06 replaces this guard with convergence.

Exact names identify candidates for reuse; structure and digest validation
govern compatibility under 03.2.02 and 03.2.06. Deletion is different:
`stop` and `--clean` remain configuration-independent and do not compute or
check a digest. Removing ownership checks makes their removal targets depend
on exact derived names regardless of provenance, structure, or digest.
03.2.04 owns the final removal inventory, home-retention policy, and warnings;
in particular, `stop` still respects that plan's stored home policy.

Ownership labels currently prevent accidental deletion of unrelated occupants
of derived names. Removing that guard deliberately makes such collisions
subject to the same explicit stop/clean behavior as jailbox-created resources.
Replace the README paragraph promising that neither command touches resources
jailbox does not own with this exact-name deletion contract and collision
tradeoff. Names and labels cannot authenticate resources against processes
with the host user's Podman authority; retain no engine socket and document
that separate threat boundary.

### Test cleanup and migration

Replace `prune_stale_jailbox_resources`, which enumerates
`label=jailbox.project`, with a ledger outside each
`/tmp/jailbox-editor-*` and `/tmp/jailbox-e2e-*` fixture. The ledger covers only
fixture-specific per-run resources, including temporary preparation helpers;
shared stage-named build caches such as `jailbox-wrapper-<stage>` and
`jailbox-test-<stage>` are excluded from registration and cleanup. Record each
resource's kind and exact name before creation. Migrate `seed_editor_server_cache` in
`tests/e2e/editor-smoke.sh` so both its home volume and its currently unnamed
helper container are covered by this registration and recovery contract.
The proxy container and image share a name, so track them independently by kind.
Remove only exact recorded objects. Stale-run pruning must establish that the
owning run has ended; preserve active runs and runs whose liveness is uncertain.
Normal teardown may remove its own run's resources. Keep ledger entries until
their resources are confirmed absent, allowing retries after failed or
interrupted cleanup even when the fixture directory has vanished.
Names do not migrate; unlabeled compatibility follows 03.2.02.

Resources left by runs predating the ledger are not automatically discovered
or pruned. Document manual inspection and exact removal for this legacy test
debris; do not introduce a one-time label or prefix sweep.

Migrate the ownership-label fixture format and refusal assertions in
`tests/unit/lifecycle.sh`. Replace the `jailbox.project` stand-in labels in
`tests/unit/config-digest.sh` while preserving coverage that homes are outside
the digest inventory and networks without a digest are incompatible.

### Acceptance criteria

- SHA-256 physical identity is consistent everywhere and no ownership label/API
  remains.
- Exact-name destructive behavior and host-authority limits are documented.
- The launch absence guard gives stop guidance for either present container
  without an ownership distinction; digest validation remains a reuse concern.
- Missing SHA-256 tooling produces a clear dependency error before resource
  operations, including for stop/clean, and hashing failure cannot yield a
  usable partial identity. Both supported tools produce the same identities.
- Cleanup regression tests cover active editor/headless runs, uncertain
  liveness, failed/interrupted cleanup retries, and interruption during cache
  seeding followed by recovery without the fixture directory.
- Existing SHA-256-derived names require no migration.
- Cleanup independently removes a recorded container and image sharing the
  proxy name, and preserves shared build caches and all unrecorded resources,
  including legacy test debris and the sandbox running the test.

### Non-goals

- Host-user authentication, resource renaming, or prefix-wide pruning.

## Implementation detail

Update `host/project-id.sh`, `host/container-runtime.sh`, `host/network.sh`,
the identified unit fixtures, lifecycle/runtime tests, test cleanup harnesses,
and README. The existing dependency diagnostic in `config_digest_hash` is a
useful model.
