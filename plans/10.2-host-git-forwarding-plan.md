# 10.2. Host Git through command forwarding

## Intent

Implement after `10.1.4-host-command-forwarding-refinements-plan.md` and before
`11.1-go-frontend-plan.md`. This plan owns Git-specific protections, the
bundled Git policy, and their integration with ordinary development, editors
and releases. Reuse general argument insertion and local fallback from the
preceding plan.

### Goal

Let ordinary Git commands work in the existing project checkout with host
credentials and without requiring callers to detect forwarding or change
their invocations. Prevent
sandbox-controlled files from determining which programs Git runs on the host.

### Git activation and policy

- Add `HOST_COMMAND_GIT` as a scalar setting (machine callers use
  `JAILBOX_CONFIG_HOST_COMMAND_GIT`). Empty is the default and disables Git
  integration. `standard` enables it with a bundled Git policy, even without
  a custom policy file. `custom`
  enables the same protections using Git rules supplied by the user.
- `HOST_COMMAND_POLICY` remains independent and can be used with either Git
  mode or on its own for other commands. A custom Git rule requires an active
  Git mode. Combine all active rules and per-section settings under the
  preceding plan's matching and validation contracts. Git-specific
  protections apply in both modes, including custom
  rules and their inserted arguments.
- The standard policy covers ordinary Git development, including staging,
  commits, fetch, pull, push and the release-request operations, as well as
  editor integration. Configuration-changing commands are excluded from the
  standard policy. A custom policy can select different invocations.
- The host resolves and snapshots the bundled policy in the same way as
  other forwarding rules. Its contents and the Git mode participate in
  compatibility checks. Document the exact bundled rules and identify policy
  changes in release notes. Preserve the ability to introduce further named
  Git profiles and other bundled policies later.

### Git protections

- Automatically mount the project's entire `.git` directory read-only in
  either Git mode. Project configuration cannot remove that protection. Host
  Git can write metadata for authorized operations; local fallback remains
  subject to the read-only mount.
- Bind every forwarded Git invocation to the registered repository and
  working tree, while preserving the mapped current directory. Use the
  host-controlled argument insertion mechanism from
  `10.1.4-host-command-forwarding-refinements-plan.md`. Prevent the original
  arguments, custom insertions or repository configuration from overriding
  that binding or the mandatory Git protections. Initially support an
  ordinary repository with a `.git` directory; exclude nested repositories,
  submodules and linked worktrees from host forwarding.
- Disable Git hooks and optional external programs for forwarded Git,
  including workspace-controlled editors, filters, merge drivers and file
  monitors. Disable recursive submodule operations and automatic maintenance
  that could launch such programs. Keep trusted host authentication tools
  available and credentials on the host. Safeguards must account for existing
  repository and host configuration, including state from earlier sessions.
  A command that cannot be executed within these protections fails explicitly.
- The policy author approves the permitted Git invocations, including remote
  and push destinations. The standard policy must restrict these to the
  intended Git operations and preserve that authority when resolving Git
  configuration. Document that forwarded pushes grant publishing authority
  as well as access to host authentication.
- An authorized Git operation such as `pull` may update protected project
  files on the host. This does not change the running forwarding snapshot.
  Users review updated configuration and policy before restarting jailbox.

### Acceptance

- Verify `.git` protection, repository binding, disabled external execution,
  and host credential isolation for both Git modes, including direct requests
  and custom insertions. Verify authorized Git writes with a controlled remote.
- Verify Git discovery, status, diff, staging, commit, fetch, pull and push
  with real VS Code and VSCodium, without an editor-specific Git path override.
- Exercise `just release --dry-run` and release-request dispatch through the
  standard policy with a test remote. No release-specific forwarding flag or
  detection is required. Migrate the temporary release Git rules in
  `jailbox.host-policy` and its activation in `jailbox.conf` to the standard
  Git mode, retaining any unrelated custom rules.
- Run development checks and affected suites; all five CI gates must pass
  before the release containing this plan.

## Implementation detail

Keep the bundled policy under `src/` so packaging installs it, and declare
the Git setting through the public API. Core owns automatic protection,
policy composition and Git-specific host checks; the frontend only passes
configuration. Reuse the forwarding service, its stream protocol, and the
argument insertion and fallback mechanisms from
`10.1.4-host-command-forwarding-refinements-plan.md`.
